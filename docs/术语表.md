# 第一章 代码是由什么组成的

这一章讲最底层的东西。你在写任何 Python 之前，其实已经在用它们了，只是没想过它们有名字。

## 1.1 值 · 名字 · 类型

### 字面量 literal ✅

**一句话**：**直接写在代码里的值**，不需要经过任何计算就能知道它是什么。

**你的代码**：

```python
ROLE_ADMIN = "admin"          # "admin" 是字面量
status_code = 409             # 409 是字面量
price = 139.0                 # 139.0 是字面量
profile = {"age": 28}         # {"age": 28} 是字面量
enabled = True                # True 是字面量
```

**易混**：字面量 vs 变量。`409` 是字面量，`status_code` 是变量。字面量是**值本身**，变量是**指向值的名字**。

**记法**：字面量就是"字面上写出来的那个东西"。

---

### 变量 variable ✅

**一句话**：**一个名字，指向一个值**。

**你的代码**：

```python
user = await self.repo.get(username)    # user 是变量，指向查出来的字典
offset = (self.page - 1) * self.size    # offset 是变量，指向算出来的数字
```

**易混**：变量的值可以换，所以叫"变"量：

```python
x = 1
x = 2       # x 现在指向 2 了
```

**记法**：Python 的变量不是"盒子"，是"标签"。`x = 1` 是把标签 `x` 贴在值 `1` 上。后面 `x = 2` 是把标签撕下来贴到 `2` 上 —— 原来的 `1` 并没有被改变，只是没人引用它了。

---

### 常量 constant ✅

**一句话**：**约定为"不该变"的变量**。

**你的代码**：

```python
# core/roles.py
ROLE_USER = "user"
ROLE_ADMIN = "admin"
```

**易混**：**Python 里没有真正的常量。** 全部大写只是一种**约定**，告诉读代码的人"这个是常量，别改"。你写了 `ROLE_USER = "admin"` 也不会有人拦你。

（对比：C++ 的 `const`、Java 的 `final` 是编译器强制的。Python 靠自觉。）

**记法**：**全大写下划线分隔 = 常量约定**。这是 PEP 8 规定的命名风格。

---

### 类型 type ✅

**一句话**：**一个值"是什么"**，决定了它能做什么操作。

**你的代码**：

```python
offset: int          # 整数
username: str        # 字符串
price: float         # 浮点数
profile: dict        # 字典
```

**易混**：`type()` 函数能查一个值的类型：

```python
>>> type("hello")
<class 'str'>
```

注意返回的是 `<class 'str'>` —— **类型本身就是类**。这是 Python 很重要的一点：`str`、`int`、`dict` 全都是类，你甚至可以继承它们。

---

### 类型注解 · 类型提示 type annotation / type hint ✅

**一句话**：写给**人和工具**看的类型说明。**运行时基本不检查。**

**你的代码**：

```python
def get(self, username: str) -> dict[str, Any] | None:
    #              ^^^^^^^^^^^^            ^^^^^^^^^^^^^^^^
    #              参数的类型              返回值的类型
```

**易混**：这是最容易误解的一点 —— **类型注解不会在运行时强制生效**。

```python
def f(x: int) -> int:
    return x

f("我是字符串")     # 完全不报错！
```

Python 是**动态类型语言**，注解只是给编辑器和 mypy 这类工具用的。真正的运行时校验得靠 Pydantic（这也是为什么 `schemas/` 那么重要）。

**记法**：`Mapped[str]`、`Annotated[...]`、`-> dict` 这些**都是注解**，不是逻辑。

---

## 1.2 表达式与语句

### 表达式 expression 🔶

**一句话**：**会产生一个值的东西**。

**你的代码**：

```python
(self.page - 1) * self.size        # 算出一个数字
user.email                          # 取出一个值
await self.repo.get(username)       # 调用得到一个结果
data.model_dump(exclude_unset=True)
```

**记法**：**能不能塞进 `print(...)` 的括号里？** 能就是表达式。

---

### 语句 statement 🔶

**一句话**：**执行一个动作的东西**。语句不产生值。

**你的代码**：

```python
if user is None:            # if 语句
    raise OutOfStock()      # raise 语句
return user                 # return 语句
import asyncio              # import 语句
x = 1                       # 赋值语句
```

**易混**：表达式 vs 语句最容易搞错的地方 —— **赋值在 Python 里是语句，不是表达式**。

所以这些写法都是语法错误：

```python
while (line = f.readline()):     # 语法错误
if (x = 1):                      # 语法错误
```

C 语言允许这么做，Python 故意禁止（防止把 `==` 写成 `=` 这种手误）。

**记法**：`if` / `for` / `while` / `return` / `import` / `def` / `class` / 赋值 —— 这些词开头的都是语句。

---

### 关键字 keyword / 保留字 reserved word 🔶

**一句话**：**语言自己征用了的词，你不能拿它们当变量名**。

**你的代码**：`if`、`else`、`for`、`while`、`def`、`class`、`return`、`import`、`from`、`as`、`with`、`try`、`except`、`finally`、`raise`、`await`、`async`、`None`、`True`、`False`、`lambda`、`pass`、`global`、`nonlocal`、`in`、`is`、`not`、`and`、`or`。

**易混**：`self` **不是**关键字，它只是约定俗成的参数名（你写成 `this` 也能跑，但所有人都会瞪你）。`cls` 同理。

---

## 1.3 函数相关

### 函数 function ✅

**一句话**：**一段有名字、可以被反复调用的代码**。

**你的代码**：

```python
def hash_password(password: str) -> str:
    raw = password.encode("utf-8")
    return bcrypt.hashpw(raw, bcrypt.gensalt()).decode("utf-8")
```

**易混**：函数 vs 方法。**方法就是"挂在类里的函数"**。`hash_password(...)` 是函数，`service.register(...)` 是方法。区别只在调用时前面有没有对象。

---

### 参数 parameter / 实参 argument 🔶

**一句话**：**参数是定义时写的名字，实参是调用时传的值。**

**你的代码**：

```python
def get(self, username: str) -> dict | None:
    #           ^^^^^^^^ 这是参数（parameter）
    ...

await repo.get("alice")
    #          ^^^^^^^ 这是实参（argument）
```

**易混**：中文日常对话里两个都叫"参数"，很容易混。英文里区分得很清楚。

**记法**：**形参 / 实参** 这对老译名更好记 —— "形"是形式上的占位符，"实"是实际传进去的东西。

---

### 位置参数 · 关键字参数 · 默认参数 🔶

**一句话**：三种传参方式。

**你的代码**：

```python
# 位置参数：按顺序对应
User("alice", "a@b.com")                     # 顺序错了就出错

# 关键字参数：点名对应，顺序无关
User(username="alice", email="a@b.com")      # 你的 models/ 里全是这种

# 默认参数：不传就用默认值
async def get_session() -> ...:
    ...

create_async_engine(url, echo=settings.DEBUG)
#                          ^^^^^^^^^^^^^^^^^^ echo 有默认值 False，这里覆盖掉了
```

**易混 —— 一个必踩的坑**：**默认参数不要用可变对象。**

```python
def add(item, bucket=[]):      # 千万别这么写！
    bucket.append(item)
    return bucket

add("a")    # ['a']
add("b")    # ['a', 'b']  ← 见鬼了
```

原因：默认值 **只在函数定义时创建一次**，所有调用共享同一个列表。正确写法是 `bucket=None`，函数体里再判断。

---

### 返回值 return value ✅

**一句话**：函数执行完交出去的结果。

**你的代码**：

```python
return _to_dict(user) if user else None
```

**易混 —— 一个你已经踩过的坑**：**函数不写 `return`，返回的是 `None`**。

你在第 4 周踩过好几次：`get_caller` 忘了 `return user`，接口就返回了 `null`，然后 `ResponseValidationError` 500。**"忘了 return"在 Python 里不会报错**，它只是安静地返回 `None`。

---

### 一等函数 first-class function 🔶

**一句话**：**函数可以像普通值一样被传来传去** —— 可以赋给变量、当参数、当返回值。

**你的代码**：

```python
Depends(get_caller)                      # 函数被当参数传出去
await conn.run_sync(Base.metadata.create_all)   # 同上
app.dependency_overrides[get_session] = override_get_session
```

**易混**：注意 `get_caller` 和 `get_caller()` 的区别 —— 前者是**函数本身**（一个值），后者是**调用它**（得到结果）。`Depends` 要的是前者。

**记法**：Python 里"函数是一个对象"这件事是所有高级用法的地基 —— 装饰器、回调、闭包全靠它。

---

### 匿名函数 lambda 🔶

**一句话**：**只能写一个表达式的、没有名字的小函数**。

**你的代码**：

```python
await with_heartbeat(
    "假异步", lambda: asyncio.gather(*(fake_async_hash(f"假{i}") for i in range(3)))
)
```

**易混**：`lambda` 的冒号后面**只能是一个表达式**，不能是语句。所以不能写 `lambda: (print(1); return 2)`。

**记法**：`lambda x: x + 1` 完全等价于 `def f(x): return x + 1`，只是不用起名字。**能用 `lambda` 的地方，通常也能用一个普通函数代替** —— 用 `lambda` 只是因为它短。

---

## 1.4 可变性

### 可变 mutable / 不可变 immutable ⬜

**一句话**：**创建之后还能不能改内容。**

| 不可变 | 可变 |
| --- | --- |
| `int`、`float`、`str`、`bool`、`tuple`、`frozenset`、`None` | `list`、`dict`、`set` |

**你的代码**：`_hits: dict[str, list[float]] = {}` 里的 dict 和 list 都是可变的 —— 所以 `clean_state` 里要 `.clear()` 而不是重新赋值。

**易混 —— 这是个大坑**：

```python
a = [1, 2, 3]
b = a              # b 和 a 指向同一个列表，不是复制！
b.append(4)
print(a)           # [1, 2, 3, 4]  ← a 也变了
```

要真复制得写 `b = a.copy()` 或 `b = list(a)`。

**记法**：**赋值从来不复制**（除了少数例外）。它只是"多贴了一个标签"。

---

### 引用 reference ⬜

**一句话**：变量里存的**是值的内存地址**，不是值本身。

**易混**：这解释了上一节那个 `b.append(4)` 的问题 —— `a` 和 `b` 是两个标签，贴在同一块内存上。

Python 里所有变量都是引用，没有 C++ 那种"值传递 vs 引用传递"的区分。区别只在于**你传的那个对象本身可不可变**。

---

### None ⬜

**一句话**：**"什么都没有"**。它自己是一个值，类型是 `NoneType`。

**你的代码**：

```python
return _to_dict(user) if user else None
profile: Mapped[dict | None] = mapped_column(JSON)
```

**易混**：
- `None` **不是** `0`、`""`、`False`
- 但它们在 `if` 判断里**都是假值**（见下一条）
- 判断"是不是 None"要用 `is None`，不要用 `== None`

---

### 真值 · 假值 truthy / falsy ⬜

**一句话**：**在 `if` 里被当成真/假的东西**。

假值只有这几个：`False`、`None`、`0`、`0.0`、`""`、`[]`、`{}`、`()`、`set()`。**其他一切都是真值。**

**你的代码**：

```python
return _to_dict(user) if user else None
#                        ^^^^ user 是 None 或字典
```

**易混 —— 这里有个陷阱**：`if user:` 和 `if user is not None:` **不是一回事**。

```python
user = {}          # 空字典
if user:           # False！走 else 分支
if user is not None:   # True！走 if 分支
```

字典查询的结果不可能是空字典（要么有数据要么 `None`），所以你的代码没问题。但**换一个场景就会出事** —— 比如数量 `0` 会被当成"没有"。

# 第二章 面向对象

这一章是一整个体系，建议整章连起来读，不要跳。

## 2.1 类与实例

### 类 class ✅

**一句话**：**一份图纸**。定义一类东西有哪些属性、能做什么。

**你的代码**：

```python
class UserService:
    def __init__(self, repo: UserRepository):
        self.repo = repo

    async def register(self, user: UserCreate) -> dict[str, Any]:
        ...
```

**记法**：类名用**大驼峰**（`UserService`、`UserRepository`）—— 这是 PEP 8 的规定，看到大驼峰就知道是类。

---

### 对象 object ✅

**一句话**：**Python 里的一切都是对象**。

**易混**：这是最容易被讲乱了的一个词，因为它有两个用法：

**用法一（泛指）**：任何有类型、有值的东西都是对象。数字 `1` 是对象，函数是对象，类也是对象。

**用法二（具体）**：由某个类造出来的东西。`UserService(repo)` 造出来的那个东西就是"一个对象"。

---

### 实例 instance ✅

**一句话**：**强调"由某个类造出来的"的那个对象**。

**你的代码**：

```python
repo = UserRepository(session)     # 这是 UserRepository 的一个实例
service = UserService(repo)        # 这是 UserService 的一个实例
```

**易混 —— 对象 vs 实例**：

**它们指的是同一个东西，只是说话的角度不同。**

- "对象" 是泛称，任何东西都是对象。
- "实例" 强调**出生来源** —— "它是从 `UserService` 这张图纸出来的"。

所以 `service` 既是一个对象，也是 `UserService` 的一个实例。说哪个都对。

**记法**：`isinstance(x, UserService)` —— 这个内置函数的名字直译就是"**x 是不是 UserService 的一个实例**"。看到 `instance` 就想"从哪个类来的"。

---

### self 🔶

**一句话**：**实例方法里的第一个参数，指"我自己这个实例"**。

**你的代码**：

```python
class UserService:
    def __init__(self, repo: UserRepository):
        self.repo = repo          # 把 repo 存到"我自己"身上

    async def register(self, user: UserCreate):
        if await self.repo.exists(user.username):     # 从"我自己"身上取出来
            ...
```

**易混**：`self` **不是关键字**，它是普通参数名，只是所有 Python 程序员都约定用 `self`。你也可以写成 `this`，代码能跑，但没人会这么干。

**更重要的一个点**：`self` 在**调用时是自动传的**，你不用写：

```python
service.register(user)          # 你写的
UserService.register(service, user)   # Python 实际做的
```

**记法**：看到方法定义里有 `self`，就知道这个方法**必须由一个实例来调用**。

---

### 构造器 constructor / `__init__` ✅

**一句话**：**造实例的时候自动跑的初始化函数**。

**你的代码**：

```python
class UserRepository:
    def __init__(self, session: AsyncSession):
        self.session = session
```

`UserRepository(session)` 一执行，`__init__` 就被自动调用，把 `session` 存到实例上。

**易混**：
- `__init__` 是**初始化**，不是**创建**。实例对象在你写 `UserRepository(...)` 那一刻就已经被创建出来了，`__init__` 紧接着负责给它装填数据。
- 真正的"创建"是 `__new__`，你几乎永远不会碰它。

**记法**：`__xxx__` 这种两边双下划线的名字叫**魔法方法 / 特殊方法（dunder method）**，它们是 Python 语言预留的钩子。`__init__`（造对象时）、`__aenter__`（`async with` 进入时）、`__await__`（`await` 时）都是。

---

### 属性 attribute ✅

**一句话**：**挂在对象上的数据或方法**。

**你的代码**：

```python
service.repo          # 属性，指向一个 UserRepository 实例
user.email            # 属性，指向一个字符串
task.done()           # 方法也是属性的一种
```

**易混**：属性 vs 变量。

- **变量**是"单独存在的名字"：`offset = 5`
- **属性**是"挂在某个对象上的名字"：`pagination.offset`

严格说方法是"可调用的属性"，但日常说话里：
- 说"属性"通常指**数据**（`self.repo`）
- 说"方法"指**函数**（`self.register`）

**记法**：**写的时候有没有点号**。`user.email` 里 `email` 就是 `user` 的属性。

---

### 方法 method ✅

**一句话**：**定义在类里面、第一个参数是 `self` 的函数**。

**你的代码**：

```python
async def register(self, user: UserCreate) -> dict[str, Any]:
```

**易混**：函数 vs 方法。

| | 定义在哪 | 怎么调用 |
| --- | --- | --- |
| 函数 | 模块顶层 | `hash_password(...)` |
| 方法 | 类里面 | `service.register(...)` |

**本质上方法就是函数**，只是它被"绑"在了实例上，所以调用时 `self` 自动传进去。

---

### 实例变量 instance variable ✅

**一句话**：**每个实例各有一份的变量**，在 `__init__` 里用 `self.x = ...` 创建。

**你的代码**：

```python
class UserRepository:
    def __init__(self, session: AsyncSession):
        self.session = session        # 实例变量
```

每个 `UserRepository` 实例有自己的 `session`，互不干扰。

---

### 类变量 class variable ✅

**一句话**：**所有实例共享一份的变量**，直接写在类体里（不在 `__init__` 里）。

**你的代码**：

```python
class User(Base):
    __tablename__ = "users"           # 类变量
    username: Mapped[str] = mapped_column(...)    # 这也是类变量

class Settings(BaseSettings):
    APP_NAME: str = "FastAPI App"      # 类变量
    model_config = SettingsConfigDict(...)        # 类变量
```

**易混 —— 实例变量 vs 类变量**：

| | 写在哪儿 | 几份 | 怎么访问 |
| --- | --- | --- | --- |
| 实例变量 | `__init__` 里 `self.x = ...` | 每个实例一份 | 只能通过实例 |
| 类变量 | 类体里直接 `x = ...` | 全类共用一份 | 类和实例都能访问 |

**陷阱**：给类变量赋值会"凭空造出一个实例变量"：

```python
class C:
    items = []          # 类变量

a = C()
a.items = [1]           # 这不会改类变量，而是给 a 造了一个新的实例变量！
C.items                 # 还是 []
```

**还有一个陷阱**：类变量如果是**可变对象**（list/dict），所有实例会共享它：

```python
class C:
    items = []          # 危险！

a, b = C(), C()
a.items.append(1)
print(b.items)          # [1]  ← b 也中招了
```

**记法**：**类变量用不可变的值是安全的**（字符串、数字）。要用列表就用 `None` 占位，在 `__init__` 里赋值。

> 顺带纠正一个可能的误解：`user_repo.py` 里那个 `_users = {}` 是**模块级变量**，不是类变量。它写在模块顶层，整个模块里所有代码都能直接访问它。效果上"所有实例共享"，身份上不是类变量。

---

## 2.2 三种方法

这三种必须一起记，差别只在**装饰器**和**第一个参数**。

### 实例方法 instance method ✅

**一句话**：**需要具体实例才能调用的方法**。

```python
class UserService:
    async def register(self, user: UserCreate):    # 有 self
```

- 装饰器：无
- 第一个参数：`self`（实例）
- 能拿到：实例属性和类属性都能拿

**什么时候用**：绝大多数情况。

---

### 类方法 classmethod ✅

**一句话**：**第一个参数是类本身，不是实例**。

**你的代码**：

```python
# schemas/user.py
@field_validator("password")
@classmethod
def password_within_bcrypt_limit(cls, value: str) -> str:
    if len(value.encode("utf-8")) > 72:
        raise ValueError("密码过长")
    return value
```

- 装饰器：`@classmethod`
- 第一个参数：`cls`（类本身）
- 能拿到：类属性，拿不到实例属性

**为什么要用它**：Pydantic 的校验器**必须**是类方法。原因是：**校验发生在对象被造出来之前** —— 那一刻还没有实例，没法传 `self`，只能传"是哪个类在问"。

**什么时候用**：需要在"还没有实例"的阶段做事的时候。另一个常见用途是"备用构造器"：

```python
class User:
    @classmethod
    def from_dict(cls, data: dict):
        return cls(**data)      # cls(...) 等价于 User(...)
```

**记法**：`cls` 和 `self` 长得像，一字之差 —— **`cls` 是类，`self` 是实例。**

---

### 静态方法 staticmethod ⬜

**一句话**：**既不拿 `self` 也不拿 `cls`，就是个"挂在类名下的普通函数"**。

```python
class MathHelper:
    @staticmethod
    def add(a: int, b: int) -> int:
        return a + b

MathHelper.add(1, 2)       # 不需要造实例
```

- 装饰器：`@staticmethod`
- 第一个参数：无
- 能拿到：什么都拿不到

**易混**：静态方法 vs 类方法。判别标准是**你需要 `cls` 吗？**

- 需要 `cls` → 类方法
- 什么都不需要 → 静态方法

**什么时候用**：几乎不用。它存在的意义主要是"把工具函数归归类、别污染模块命名空间"。在 Python 里，很多时候直接写个模块级函数更清楚。

**记法**：`staticmethod` 里那个 `static` 和你想的"静态"没关系，它就是"不动、不依赖任何状态"。

---

### `property` 属性访问器 ✅

**一句话**：**让一个方法看起来像一个属性** —— 访问时不用写括号。

**你的代码**：

```python
# api/deps.py
class Pagination:
    @property
    def offset(self) -> int:
        return (self.page - 1) * self.size

    @property
    def limit(self) -> int:
        return self.size
```

用的时候：

```python
pagination.offset       # 不是 pagination.offset()
pagination.limit
```

**为什么要用**：`offset` 不是"存下来的数据"，而是"每次算出来的"。如果写成普通属性，就得在 `__init__` 里算一次存起来，`page` 变了还得重算。用 `@property` 就变成"每次取都现算"，而且**用起来和普通属性一样**。

**易混**：`@property` 后面还可以跟 `@xxx.setter` 定义"赋值时的行为"，你还没用到。

---

## 2.3 继承与多态

### 继承 inheritance ✅

**一句话**：**子类自动获得父类的属性和方法**。

**你的代码**：

```python
class User(Base):                      # User 继承 Base
class UsernameAlreadyExists(BusinessError):   # 继承业务异常
class Settings(BaseSettings):          # 继承 Pydantic 的设置基类
```

**易混 —— 一个常见的理解偏差**：继承不只是"复制一份父类的东西"。

更重要的是**"是一种"关系**：`UsernameAlreadyExists` **是一种** `BusinessError`。所以下面这行成立：

```python
except BusinessError:      # 能捕获 UsernameAlreadyExists
```

这个"能捕获所有子类"的能力，就是多态（见下）。

**记法**：**继承 = "is-a" 关系**。读到 `class A(B)`，就念成"A 是一种 B"。

---

### 方法解析顺序 MRO · `super()` ⬜

**一句话**：**Python 找方法时按什么顺序往上找**。

顺序是：**自己 → 父类 → 祖父类 → ... → object**。

`super()` 是"从父类那一层开始找"：

**你的代码**：

```python
class UsernameAlreadyExists(BusinessError):
    def __init__(self, username: str):
        super().__init__(f"用户名 '{username}' 已被注册")
        self.status_code = 409
```

`super().__init__(...)` 的意思是"调用父类 `BusinessError` 的 `__init__`，把消息传给它处理"，然后子类再补一句自己的 `status_code`。**这是重写时最常见的写法：先让父类干它那份活，再加上自己的。**

---

### 重写 override ✅

**一句话**：**子类重新实现父类的同名方法**。Python 完全支持。

**你的代码**：

```python
class BusinessError(Exception):
    def __init__(self, message: str, headers: dict | None = None):
        super().__init__(message)
        self.message = message
        self.status_code = 400
        self.headers = headers

class UsernameAlreadyExists(BusinessError):
    def __init__(self, username: str):
        super().__init__(f"用户名 '{username}' 已被注册")
        self.status_code = 409        # ← 重写了父类设的 400
```

子类**重写**了父类的 `__init__`，并且覆盖了 `status_code` 的值。

**易混**：重写 vs 重载（下一条）。

---

### 重载 overload ⬜ ⚠️

**一句话**：**同名函数、参数不同、逻辑不同**。

**⚠️ Python 根本不支持函数重载。**

在 Java 里可以这样：

```java
void f(int x) { ... }
void f(String s) { ... }     // 两个 f 共存，按参数类型选
```

Python 里这样写，**第二个直接把第一个覆盖掉**：

```python
def f(x: int): print("整数版")
def f(x: str): print("字符串版")

f(1)      # 打印"字符串版"！第一个 f 已经不存在了
```

**Python 里两个名字带 overload 的东西，都不是这个意思**：

1. `typing.overload` —— 只是写给类型检查器看的注释，**运行时完全不生效**：

```python
from typing import overload

@overload
def f(x: int) -> int: ...
@overload
def f(x: str) -> str: ...
def f(x):                    # 真正生效的只有这最后一个
    ...
```

2. Pydantic / FastAPI 做的"一个接口处理多种输入" —— 那是**运行时判断类型**，不是语言级的重载。

**记法**：**在 Python 语境里听到"重载"，99% 是在说别的东西。** 谁跟你说 Python 有函数重载，谁大概率是从 Java 转过来的。

**易混**：中文里"重写"和"重载"只差一个字，英文 `override` / `overload` 也像。记法：

- **重写 = 覆盖父类**（override，有 over-ride，"骑在父类头上"）
- **重载 = 加载多个版本**（overload，有 over-load，"多装几个"）—— Python 没有

---

### 多态 polymorphism ✅

**一句话**：**同一个操作，作用在不同对象上，表现出不同行为**。

**你的代码 —— 这是最好的例子**：

```python
# core/errors.py
async def business_error_handler(request: Request, exc: BusinessError):
    return JSONResponse(
        status_code=exc.status_code,        # ← 关键在这一行
        content={"code": exc.status_code, "message": exc.message},
    )
```

这个处理器**完全不认识** `UsernameAlreadyExists`、`OutOfStock`、`BookAlreadyExists` 这些子类。它只知道"你是个 `BusinessError`，我问你要 `status_code` 和 `message`"。

而每个子类给出的答案不一样：409、400、409……

**处理器只有一份代码，却处理了七八种不同的错误 —— 这就是多态。**

**易混**：多态不是 Python 独有的，几乎所有面向对象语言都有。但在 Python 里它有个更强的版本叫**鸭子类型**：

> "如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。"

意思是 Python **不看你的类型是什么，只看你有没有那个方法**。你只要写个类，有 `status_code` 和 `message` 两个属性，就能被这个处理器正确处理 —— 哪怕它根本没继承 `BusinessError`。

（对比：Java 要求你必须显式实现某个接口。Python 不要求。这叫**结构化类型**。）

---

### 封装 encapsulation ✅

**一句话**：**把细节藏起来，只暴露必要的接口**。

**你的代码 —— 三个层次都体现了封装**：

**层次一：类的封装。** `UserService` 对外只暴露 `register`、`get_user` 这些方法，调用者完全不知道里面用了什么仓储、怎么查重。

**层次二：模块的封装。** `_to_dict` 用下划线开头 —— 这是 Python 的约定：**下划线开头的名字是"内部的，别碰"**。

```python
def _to_dict(user: User) -> dict[str, Any]:
```

`_users`、`_hits`、`_books` 同理。

**层次三：分层架构的封装。** 这是第 4 周你亲手做的那件事：路由器不知道数据存在哪，服务层不知道 SQL 怎么写，仓储层不知道 HTTP 是什么。

**易混 —— Python 的封装是"君子协定"**：

```python
service._to_dict()      # 能调用，不会报错
```

Python **没有** Java 的 `private` 关键字。下划线纯粹是**约定**：告诉别人"这是内部的，你用了出问题别找我"。

（有两个下划线开头的 `__xxx`，那会触发"名字改写"，稍微强制一点，但你还没用到。）

**记法**：封装的目的不是"防止别人偷看"，是**"降低别人理解你的成本"** —— 别人只需要知道有 `register` 这个方法能注册用户，不需要知道里面怎么查重。

---

### 抽象类 abstract class ⬜

**一句话**：**只能被继承、不能被直接实例化的类**，用来约束子类必须实现某些方法。

**易混**：Python 没有语言级的 `abstract` 关键字，要用 `abc` 模块：

```python
from abc import ABC, abstractmethod

class Repository(ABC):
    @abstractmethod
    async def get(self, key): ...
```

**⚠️ 但是在你这个项目里，别用抽象类。** 原因是 Python 有鸭子类型 —— 你完全可以在需要的时候直接换掉一个实现（就像第 11 周你把 `UserRepository` 从内存改成 SQL，`UserService` 一行没改），不需要提前定义一个抽象接口。

抽象类在 Python 社区里是有争议的用法，很多人认为它把 Java 的思维带了进来。**知道它存在就够了。**

---

### 协议 protocol · 鸭子类型 duck typing ⬜

见上面「多态」词条里的说明。简单说：**Python 不要求你声明"我实现了某个接口"，只看你有没有那个方法**。

---

## 2.4 特殊方法

### 魔法方法 · dunder method 🔶

**一句话**：**两边双下划线的方法**（dunder = **d**ouble **under**score），是 Python 给类预留的"钩子"。

**你的代码里出现过的**：

| 方法 | 什么时候被自动调用 |
| --- | --- |
| `__init__` | `UserRepository(session)` 造实例时 |
| `__aenter__` | `async with X` 进入时 |
| `__aexit__` | `async with X` 退出时 |
| `__call__` | `instance()` 把一个对象当函数用时 |
| `__await__` | `await X` 时 |
| `__iter__` | `for x in obj` 时 |

**易混**：`__init__` 这种名字你**不应该直接调用**。虽然 `user.__init__(...)` 能跑，但那是错误用法 —— 魔法方法是"给 Python 调用的"，你写 `User(...)` 就行。

**记法**：**看到 `__xxx__` 就知道"这是语言层面的约定，不是普通方法"。**

---

### `__call__` ✅

**一句话**：**让实例可以像函数一样被调用**。

**你的代码**：

```python
# api/deps.py
def rate_limiter(scope: str, times: int, window: int):
    async def limiter(request: Request) -> None:
        ...
    return limiter

login_rate_limit = rate_limiter("auth:token", 5, 60)
# 然后：Depends(login_rate_limit)
```

`Pagination` 也是 —— 第 5 周学的"类作为依赖"，FastAPI 会去调用类本身来造实例，靠的就是类也有 `__call__`（准确说 Python 的 `类(...)` 语法本身）。

# 第三章 组织代码

## 3.1 模块 · 包 · 导入

### 模块 module ✅

**一句话**：**一个 `.py` 文件就是一个模块。**

**你的代码**：`core/db.py`、`repositories/user_repo.py`、`schemas/user.py` 各是一个模块。

**易混**：模块 vs 包（下一条）。

---

### 包 package ✅

**一句话**：**一个包含 `__init__.py` 的文件夹**，里面装着一组模块。

**你的代码**：

```
src/my_fastapi_project/
├── api/               ← 包
│   ├── __init__.py
│   ├── deps.py        ← 模块
│   └── routers/       ← 包
│       ├── __init__.py
│       ├── user.py    ← 模块
│       └── book.py    ← 模块
├── core/              ← 包
├── models/            ← 包
├── repositories/      ← 包
├── schemas/           ← 包
└── services/          ← 包
```

**易混 —— 一个你踩过的坑**：

`__init__.py` 在 Python 3.3 之后**技术上可以不要**（叫"命名空间包"），但**你的项目必须要有**。原因见「`__init__.py` / `__all__`」那一条。

---

### 导入 import ✅

**一句话**：**把别的模块里的东西拿过来用**。

**你的代码 —— 四种写法**：

```python
import asyncio                              # 导入整个模块
from typing import Annotated                # 从模块里导入一个名字
from sqlalchemy.ext.asyncio import (        # 一次导入多个
    AsyncEngine,
    async_sessionmaker,
    create_async_engine,
)
from my_fastapi_project.models import Book, User
```

**易混 —— 绝对导入 vs 相对导入**：

你的项目用的是**绝对导入**（从 `my_fastapi_project` 开头写完整路径），这是推荐的写法。另一种是相对导入：

```python
from .user import User          # . 表示当前包
from ..core.db import Base      # .. 表示上一层包
```

你**没有**用相对导入，保持现状就行 —— 绝对导入更清楚，移动文件时也不容易出错。

**导入顺序的规则**（ruff 的 `I` 规则在管）：

```python
# 第一组：标准库
import asyncio
from typing import Annotated

# 第二组：第三方库
from fastapi import APIRouter
from sqlalchemy import select

# 第三组：自己的项目
from my_fastapi_project.core.db import Base
```

**组与组之间空一行，组内按字母排。** 这个顺序不是随便定的 —— 一眼就能看出"这个文件依赖了多少外部东西"。

---

### `__init__.py` / `__all__` ✅

**一句话**：`__init__.py` 让文件夹变成包；`__all__` 声明这个包对外提供哪些名字。

**你的代码**：

```python
# models/__init__.py
from my_fastapi_project.models.book import Book
from my_fastapi_project.models.user import User

__all__ = ["Book", "User"]
```

**⚠️ 这个文件的作用远比看起来重要 —— 见「副作用导入」。**

---

### 副作用导入 side-effect import 🔶

**一句话**：**import 的目的不是用那个名字，而是触发那个模块的代码执行。**

**你的代码**：

```python
# models/__init__.py
from my_fastapi_project.models.book import Book
from my_fastapi_project.models.user import User
```

这两行 `import` 的真实目的**不是**为了用 `Book` 和 `User` 这两个名字，而是为了让 `class Book(Base)` 和 `class User(Base)` 这两行**被执行**。

因为 SQLAlchemy 是**靠"类被定义过"来注册表的**。如果某个模型文件从头到尾没被 import，那个类就从没被定义，`Base.metadata` 里也就没有它的表 —— 建表时会被**静默漏掉**，一句错都不报。

**这也是 `__all__` 在这里的第二个作用**：ruff 的 `F401` 规则会提示"你导入了但没用"，`__all__` 是在说"我就是故意导入它们触发的"。

---

## 3.2 名字住在哪里

### 命名空间 namespace ⬜

**一句话**：**名字的"地址空间"**。不同命名空间里的同名变量互不干扰。

**你的代码**：

```python
# repositories/user_repo.py
def _to_dict(user): ...

# repositories/book_repo.py
def _to_dict(book): ...
```

两个文件里各有一个 `_to_dict`，**互不影响** —— 因为它们住在不同的命名空间（各自的模块）里。

**记法**：**命名空间就是"名字的户口本"**。同一个名字可以在不同户口本上重复。

---

### 作用域 scope 🔶

**一句话**：**一个名字在代码的哪个范围内能被访问到**。

Python 的查找顺序叫 **LEGB**：

| 字母 | 全称 | 含义 |
| --- | --- | --- |
| **L** | Local | 当前函数内部 |
| **E** | Enclosing | 外层函数（闭包用） |
| **G** | Global | 模块顶层 |
| **B** | Built-in | Python 内置（`print`、`len`、`ValueError`） |

**查找是从内往外**：先在 L 找，找不到去 E，再找不到去 G，最后去 B。都没找到就 `NameError`。

**你的代码**：

```python
# scripts/blocking_demo.py
async def with_heartbeat(label: str, make_work) -> None:
    beats = 0                        # ← E 层（外层函数）
    async def heartbeat() -> None:
        nonlocal beats               # ← 声明"我改的是 E 层的 beats"
        while True:
            await asyncio.sleep(0.05)
            beats += 1               # ← 改的是 E 层的
```

---

### global / nonlocal 🔶

**一句话**：**告诉 Python"我改的不是本地变量，是外面那个"。**

**你的代码**：

```python
async def with_heartbeat(label: str, make_work) -> None:
    beats = 0
    async def heartbeat() -> None:
        nonlocal beats        # ← 关键就是这一行
        while True:
            await asyncio.sleep(0.05)
            beats += 1
```

**不写 `nonlocal` 会怎样？**

```python
def outer():
    x = 0
    def inner():
        x += 1        # UnboundLocalError!
    inner()
```

Python 看到 `x += 1`（也就是 `x = x + 1`），认为 `x` 是 `inner` 的**局部变量**，于是去找它自己的 `x` —— 还没赋值就用了，报错 `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`。

`nonlocal x` 是在说"**别在我这儿找，去外层函数找**"。

- `nonlocal` —— 往外找**一层函数**
- `global` —— 直接指向**模块顶层**

**记法**：**"只读不用声明，要改必须声明。"** 如果只是读外层的变量，Python 会自动往上找；只有要**赋值**时才需要 `nonlocal` / `global`。

---

## 3.3 环境与依赖

### 虚拟环境 venv ✅

**一句话**：**一个项目专属的、隔离的 Python 环境**。

**你的代码**：项目根目录的 `.venv/`。

**为什么需要它**：如果不隔离，你机器上所有项目共用一个 Python，A 项目要 `pydantic 1.x`、B 项目要 `2.x`，就会打起来。虚拟环境给每个项目一套独立的第三方库。

**你的项目里的三个东西**：

| 东西 | 作用 |
| --- | --- |
| `.venv/` | 虚拟环境本体（**不提交到 git**，在 `.gitignore` 里） |
| `pyproject.toml` | 声明"我这个项目需要哪些库"（**提交**） |
| `uv.lock` | 精确锁定"每个库装哪个版本"（**提交**） |

**易混**：`pyproject.toml` 是"我要求装什么"（可能写 `fastapi>=0.141.1`），`uv.lock` 是"实际装了哪个版本"（精确到 `0.141.1`）。前者是人写的，后者是工具生成的。

---

### 依赖 dependency ✅

**一句话**：**一个东西完成工作所必须用到的另一个东西。**

**⚠️ 这个词在你的项目里有三个完全不同的意思，看到时先问是哪个场景：**

**意思一：代码依赖（架构层面）** —— 第 4 周那条规矩：

```
routers → deps → services → repositories
```

`UserService` 依赖 `UserRepository`。这个依赖是**代码写死的**。

**意思二：FastAPI 的依赖注入** —— 第 5 周的主角：

```python
async def get_user_service(
    repo: Annotated[UserRepository, Depends(get_user_repo)],
) -> UserService:
```

`get_user_service` **依赖** `get_user_repo`。这个依赖是**框架在运行时自动装配的**。

**意思三：第三方库依赖** —— `pyproject.toml` 的 `dependencies` 列表。

**为什么一个词三个意思还都用同一个字**：因为它们本质是同一件事 —— **"A 需要 B 才能干活"**。区别只在"谁负责把 B 给 A"：代码里自己 `new`、框架自动注入、还是包管理器安装。

---

### 依赖注入 DI / 控制反转 IoC ✅

**一句话**：**不自己造需要的对象，而是"声明我需要什么"，让别人递给你。**

**对比着看最清楚**：

```python
# 不用依赖注入 —— 自己造
class UserService:
    def __init__(self):
        self.repo = UserRepository()      # 写死了！

# 用依赖注入 —— 别人递进来
class UserService:
    def __init__(self, repo: UserRepository):
        self.repo = repo                  # 谁来都行
```

**好处**：第二种写法里，`UserService` **不知道**也不关心 `UserRepository` 是怎么造出来的。所以：

- 测试时可以换一个假的（第 7 周你就想过这个）
- 第 11 周可以把内部的字典换成 SQL，而 `UserService` 一行不用改
- 将来换数据库时，改动被挡在仓储层里面

**"控制反转"是什么意思**：**谁来决定"用哪个实现"这件事，被反转了。**

- 原来：`UserService` 自己决定（我 new 一个 `UserRepository`）
- 现在：外面的 `deps.py` 决定（我给你哪个你就用哪个）

控制权从"用的人"转到了"装配的人"手里，所以叫**反转**。

**FastAPI 里谁负责装配**：

```python
# api/deps.py —— 这里是全部的装配逻辑
def get_user_repo(session: SessionDep) -> UserRepository:
    return UserRepository(session)

def get_user_service(repo: Annotated[UserRepository, Depends(get_user_repo)]) -> UserService:
    return UserService(repo)

UserServiceDep = Annotated[UserService, Depends(get_user_service)]
```

`deps.py` 就是整个应用的**装配车间**。第 4 周把它单独抽出来，今天你看到好处了。

# 第四章 函数进阶

## 4.1 迭代

### 可迭代对象 iterable 🔶

**一句话**：**能被 `for` 循环遍历的东西**。技术上：有 `__iter__` 方法。

**你的代码**：

```python
for table in ("users", "books"):        # 元组，可迭代
for user in result.scalars():           # SQLAlchemy 的结果，可迭代
for key, value in data.items():         # 字典，可迭代
for i in range(3):                      # range 对象，可迭代
```

常见可迭代对象：`list`、`tuple`、`dict`、`set`、`str`、`range`、生成器、文件对象。

---

### 迭代器 iterator 🔶

**一句话**：**能一个一个往外吐东西的东西**。技术上：有 `__next__` 方法。

**易混 —— 这是最容易混的一组，三个词是层层递进的关系，不是并列**：

| 词 | 标志 | 能力 |
| --- | --- | --- |
| **可迭代对象 iterable** | 有 `__iter__` | 能被 `for` 遍历 |
| **迭代器 iterator** | 有 `__next__` | 能一个一个吐，**但只能往前走，走完就废** |
| **生成器 generator** | 函数里有 `yield` | 一种**自动实现**了迭代器协议的省事写法 |

**关系是**：

```
可迭代对象  --iter()-->  迭代器  --next()-->  一个一个的值
生成器  是一种  迭代器（你不用自己写 __iter__ 和 __next__）
```

**"走完就废"是什么意思**：

```python
it = iter([1, 2, 3])
list(it)      # [1, 2, 3]
list(it)      # []  ← 空了！迭代器只能用一次
```

**这就是为什么 `clean_state` 里用 `timestamps.pop(0)` 而不是遍历** —— 遍历一个列表时如果同时修改它，行为会变得难以预测。

---

### 生成器 generator ✅

**一句话**：**函数里有 `yield`，它就变成生成器 —— 一种能"暂停再继续"的函数**。

**你的代码 —— 这是全项目最重要的一个生成器**：

```python
# api/deps.py
async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionFactory() as session:
        yield session
```

（`async def` + `yield` = **异步生成器**。）

**为什么它能撑起整个 `yield` 依赖机制**：

普通函数 `return` 之后就结束了，没法"之后再干点事"。生成器可以：`yield` 交出一个值之后**暂停**在这里，等外面的人说"继续"，再从下一行往下走。

所以 FastAPI 能做到：

```
调用 get_session()
    ↓
代码跑到 yield session，交出去，暂停
    ↓
（FastAPI 把 session 注入到你的端点，端点跑完，响应发出）
    ↓
FastAPI 说"继续"，代码从 yield 的下一行继续跑
    ↓
async with 退出 → 会话关闭
```

**"交出去、暂停、之后再继续"就是生成器的全部魔法。** 你第 5 周学的 `yield` 依赖，机制就是这个。

---

### 序列 sequence 🔶

**一句话**：**有顺序、能按下标取、能切片、能 `len()` 的可迭代对象**。

**你的代码**：`str`、`list`、`tuple`。

关键特征：

```python
users[0]                    # 按下标取
users[0:3]                  # 切片
len(users)                  # 求长度
users.index(x)              # 查位置
"abc"[1]                    # 字符串也是序列
```

**易混**：**可迭代 ≠ 序列**。字典是可迭代的，但**不是序列**（不能按下标取，`d[0]` 是查 key 为 `0` 的项）。生成器也是可迭代的，但不是序列（不能 `len()`，不能切片）。

---

### 切片 slice ✅

**一句话**：**从序列里取一段** —— `序列[起点:终点:步长]`。

**你的代码**：

```python
# services/user_service.py
return users[offset : offset + limit]
#           起点       终点（不含）
```

```python
# scripts/db_check.py
text("SELECT profile FROM users WHERE username = 'bob'")
```

```python
# docs 里提到的
raw[0:2]      # 取第 0、1 两个字符
"abcdef"[1:4]     # 'bcd'
```

**三条必须记住的规律**：

1. **终点不含** —— `[0:3]` 取的是下标 0、1、2，**不是** 0、1、2、3。
2. **越界不报错** —— `[0:100]` 在只有 3 个元素的列表上，返回全部 3 个。这是切片比 `[index]` 安全的地方。
3. **不写就是"到头"** —— `[2:]` 从 2 到末尾，`[:3]` 从开头到 2。

**易混**：切片**一定会创建一个新对象**（拷贝）。所以 `users[offset : offset + limit]` 拿到的是一个新列表，改它不会影响原列表。

---

## 4.2 高级机制

### 闭包 closure 🔶

**一句话**：**函数记住了它"出生时"所在的环境**。

**你的代码 —— 你有三个闭包，只是不知道它叫这个**：

```python
# api/deps.py —— 闭包 1
def rate_limiter(scope: str, times: int, window: int):
    async def limiter(request: Request) -> None:
        key = f"{scope}:{client}"      # ← scope 哪来的？外面那个参数
        ...
    return limiter                      # ← 把内层函数送出去

login_rate_limit = rate_limiter("auth:token", 5, 60)
```

```python
# api/deps.py —— 闭包 2
def require_role(required: str):
    async def checker(caller: CallerDep):
        if caller["role"] != required:     # ← required 也被记住了
            ...
    return checker
```

```python
# scripts/blocking_demo.py —— 闭包 3
async def with_heartbeat(label: str, make_work) -> None:
    beats = 0
    async def heartbeat() -> None:
        nonlocal beats                     # ← beats 也被记住了
        ...
```

**关键点**：`rate_limiter("auth:token", 5, 60)` 执行完并返回之后，`scope`、`times`、`window` 这三个参数**应该已经被销毁了**。但 `limiter` 还能用它们 —— 因为它们被**包进了函数里**。

**记法**：**闭包 = 函数 + 它带走的环境。**

**为什么要用它**：闭包的核心用途是"**造出一批相似但略有不同的函数**"。`rate_limiter` 是一个模具，`login_rate_limit`、`books_rate_limit`、`users_rate_limit` 是从这个模具里出来的三个不同的限流器 —— 它们逻辑一样，只是参数不同。这就是第 5 周学的"**依赖工厂**"。

---

### 装饰器 decorator ✅

**一句话**：**在不改函数体的前提下，给函数套一层。**

**你的代码**：

```python
@router.get("/me", response_model=UserResponse)
async def get_me(caller: CallerDep):
    return caller
```

```python
@field_validator("password")
@classmethod
def password_within_bcrypt_limit(cls, value: str) -> str:
```

```python
@app.middleware("http")
async def add_request_id(request: Request, call_next): ...
```

```python
@lru_cache
def get_settings() -> Settings: ...
```

```python
@pytest.fixture
def client(): ...
```

```python
@property
def offset(self) -> int: ...
```

**`@` 这个语法在做什么**：

```python
@router.get("/me")
async def get_me(...): ...

# 完全等价于：
async def get_me(...): ...
get_me = router.get("/me")(get_me)
#      ^^^^^^^^^^^^^^^^^^^^^^^^^^ 把函数传给装饰器，拿返回值替换原名
```

**记法**：**装饰器就是一个"接收函数、返回函数"的函数。** 它经常靠闭包实现。

**为什么这一个语法能覆盖这么多用途**：因为"给函数套一层"这件事太通用了 —— 注册路由是一层、注册校验器是一层、包上缓存是一层、包上日志是一层。

---

### 回调 callback 🔶

**一句话**：**把一个函数当参数传出去，将来由别人在合适的时机调用。**

**你的代码**：

```python
Depends(get_caller)                      # 告诉 FastAPI"到时候调这个"
app.dependency_overrides[get_session] = override_get_session
await conn.run_sync(Base.metadata.create_all)     # 交给 run_sync 去调用
```

中间件里的 `call_next` 也是回调 —— 它是"调用链上的下一个处理者"，FastAPI 把它传给你，你说"什么时候继续往下走"。

**易混 —— 回调 vs 闭包 vs 装饰器**：

这三个经常被混成一团，其实在回答三个不同的问题：

| 词 | 回答的问题 |
| --- | --- |
| **回调 callback** | "这个函数什么时候被谁调用？" —— 别人调，不是你调 |
| **闭包 closure** | "这个函数还记得什么？" —— 记得它出生时的变量 |
| **装饰器 decorator** | "怎么不改函数体就给它加功能？" —— 套一层 |

**它们有交集**：装饰器经常用闭包实现；被装饰出来的函数经常被当回调传出去。但三者说的是三件事。

---

### 列表推导式 comprehension 🔶

**一句话**：**一行写一个"循环 + 收集"**。

**你的代码**：

```python
# repositories/user_repo.py
return [_to_dict(user) for user in result.scalars()]

# 等价于：
result_list = []
for user in result.scalars():
    result_list.append(_to_dict(user))
return result_list
```

还有**字典推导式**和**集合推导式**：

```python
{key: value for key, value in items}
{user.username for user in users}
```

**易混**：如果逻辑复杂（有多个条件、嵌套循环），**别用推导式**，老老实实写 `for`。推导式的价值是"一眼看清在做什么"，复杂了反而看不清。

# 第五章 错误处理

### 异常 exception ✅

**一句话**：**程序出错时被"抛"出来的一个对象**。

**你的代码**：

```python
# core/exceptions.py
class BusinessError(Exception):
    def __init__(self, message: str, headers: dict | None = None):
        super().__init__(message)
        self.message = message
        self.status_code = 400
        self.headers = headers

class UsernameAlreadyExists(BusinessError): ...
class OutOfStock(BusinessError): ...
```

**易混 —— 一个重要的观念转变**：

**异常不是"错误信息"，它是一个对象。** 既然它是对象，就可以：

- 继承（你自己的异常全是 `BusinessError` 的子类）
- 带属性（`status_code`、`message`、`headers`）
- 被传来传去

**这是异常处理能力的来源** —— 如果异常只是一句字符串，你就没法按类型去分辨和处理。

---

### 抛出 raise ✅

**一句话**：**主动制造一个异常，中断当前流程。**

**你的代码**：

```python
raise UsernameAlreadyExists(user.username)
raise InvalidCredentials()
raise OutOfStock()
```

**易混 —— 一个你已经踩过的坑**：

```python
raise OutOfStock()      # 正确：抛出异常
return OutOfStock()     # 错误：把一个异常对象当返回值交出去
```

你在第 4 周踩过这个坑。`return OutOfStock()` 不会报错，它会安静地把一个异常对象返回给上层，然后上层拿它当普通数据用 —— 结果是一堆莫名其妙的错误。

**记法**：**`raise` 是"引爆"，`return` 是"交货"。** 这两个动词千万别混。

---

### 捕获 catch / except ✅

**一句话**：**接住抛出来的异常，别让它继续往上跑。**

**你的代码**：

```python
# core/security.py
try:
    return decode_access_token(token)
except jwt.InvalidTokenError:
    raise InvalidCredentials()
```

```python
# api/deps.py
try:
    payload = decode_access_token(token)
except jwt.InvalidTokenError:
    raise InvalidCredentials()
```

**易混 —— `except Exception` 是个陷阱**：

```python
try:
    do_something()
except Exception:          # 捕获一切
    pass                   # 什么都不做
```

这会把所有错误（包括你打错字造成的 `NameError`）都吞掉，然后程序带着错误的状态继续跑，最后在别的地方炸掉 —— **报错位置和真正的问题位置隔了十万八千里**。

正确做法是**只捕获你预期的那种异常**，让它明确地告诉你出了什么事。

---

### `finally` / `else` ✅

**一句话**：`finally` 是"不管成不成功都要跑"；`else` 是"只有没出错才跑"。

**你的代码**：

```python
# tests/test_database.py
try:
    ...
finally:
    await engine.dispose()
```

```python
# repositories/user_repo.py（第 5 周学 yield 依赖时的写法）
session = FakeSession()
try:
    yield session
finally:
    session.close()
```

**易混 —— 完整的 `try` 有四个部分**：

```python
try:
    正常逻辑
except SomeError:
    出错了怎么办
else:
    没出错时才跑（罕见，但存在）
finally:
    无论如何都要跑（清理工作）
```

**为什么 `finally` 这么重要**：**它是"资源一定会被释放"的保证。** 数据库连接、文件句柄、锁 —— 这些东西漏掉一个，程序跑一阵子就会耗尽资源。

**记法**：`finally` 里的代码，**除非进程被杀，否则一定会执行**。

---

### 异常链 `raise ... from ...` ⬜

**一句话**：**保留"原始异常"的信息，同时抛出新的异常**。

```python
try:
    payload = decode_access_token(token)
except jwt.InvalidTokenError as exc:
    raise InvalidCredentials() from exc      # ← 保留原因
```

不加 `from exc` 时，Python 也会自动把原来的异常挂在 `__context__` 上（显示成 "During handling of the above exception, another exception occurred"）。加 `from` 是显式声明因果关系。

**为什么重要**：调试时你看到的是最外层的异常，但如果不知道"它是由哪个底层异常引起的"，就要一层层猜。

---

### 断言 assert ✅

**一句话**：**"我确信这里应该是这样，如果不是就炸"**。

**你的代码**：

```python
# tests/test_database.py
assert book is not None
assert book.title == "流畅的Python"
```

```python
# 第 9 周实验脚本里
assert statuses == [201] * CONCURRENT, f"状态码异常: {statuses}"
```

**易混 —— `assert` 在生产代码里要小心**：

```python
python -O your_script.py       # -O 参数会让所有 assert 被跳过！
```

所以 `assert` **不能用来做真正的校验**（比如"用户必须有权限"），只能用来说明"程序员的假设"。真正的校验要用 `if ... raise`。

**记法**：**assert 是写给"读代码的人"看的，不是写给"用户"看的。**

---

### 自定义异常 ✅

**一句话**：**定义自己的异常类，用来表达业务上的错误**。

**你的代码**：整个 `core/exceptions.py`。

**为什么要自定义**：因为标准异常（`ValueError`、`KeyError`）**没法表达业务语义**。

```python
raise OutOfStock()          # 一眼就知道：库存不够
raise ValueError("...")     # 一眼只知道：值有问题
```

**这也是多态的最佳实践场**：所有业务异常继承 `BusinessError`，全局处理器只需要认识 `BusinessError` 一个，就能处理全部七八种业务错误。

# 第六章 数据与表示

## 6.1 序列化

### 序列化 serialize ✅

**一句话**：**把对象变成"可以传输或存储"的格式**。

**你的代码**：

```python
data = book.model_dump()                     # Pydantic 对象 → 字典
session.add(User(profile={"age": 28}))       # 字典 → 数据库里的 JSON 文本
JSONResponse(content={"code": 409, ...})     # 字典 → JSON 字符串
```

**易混 —— 序列化 vs 编码（下一条）**：它们不是一回事，是**上下两层**。

---

### 反序列化 deserialize ✅

**一句话**：**反过来** —— 从传输/存储格式还原成对象。

**你的代码**：

```python
UserCreate(**payload)              # 字典 → Pydantic 对象（顺带校验）
user.profile                       # 数据库里的 JSON 文本 → Python 字典
BookResponse.model_validate(book)  # 字典 → 响应模型
```

**易混**：FastAPI 帮你做的事里，**一半是反序列化（进）一半是序列化（出）**：

```
请求进来 → JSON 字节 → 字典 → Pydantic 模型    （反序列化）
响应出去 → Pydantic 模型 → 字典 → JSON 字节    （序列化）
```

---

### 编码 encoding / 解码 decode ✅

**一句话**：**字符串 ↔ 字节之间的转换**。

**你的代码**：

```python
# core/security.py
raw = password.encode("utf-8")              # 字符串 → 字节
return bcrypt.hashpw(raw, bcrypt.gensalt()).decode("utf-8")    # 字节 → 字符串
```

```python
# schemas/user.py
if len(value.encode("utf-8")) > 72:          # 量的是字节数，不是字符数
```

**易混 —— 序列化 vs 编码，这两层经常被混**：

```
Python 对象（dict）
      ↓ 序列化
JSON 字符串（str）
      ↓ 编码
字节（bytes）
      ↓
通过网络传出去
```

**序列化**是"对象 → 文本"，**编码**是"文本 → 字节"。前者是格式转换，后者是字符集转换。

**你踩过的坑就是这里**：bcrypt 的 72 是**字节**上限。一个中文字符 UTF-8 编码后占 **3 个字节**，所以 24 个中文就满了。**字符数 ≠ 字节数。**

---

### 字符集 · Unicode · UTF-8 🔶

**一句话**：`Unicode` 是"给每个字符编个号"的**标准**；`UTF-8` 是把这个编号**变成字节**的**具体方案**。

**易混**：

- **Unicode** 是字符和编号的对应表。汉字"中"的编号是 U+4E2D。
- **UTF-8** 是"怎么把这个编号存成字节"的规则。"中" → `E4 B8 AD`（3 字节）。
- **ASCII** 是更老的标准，只能表示 128 个字符（英文 + 控制符）。

**你的代码**：`env_file_encoding="utf-8"`、`encode("utf-8")`。

**你踩过的坑**：`raw.encode("uft-8")` 打错了字（`uft` 不是 `utf`），结果 17 个测试连环失败，报 `LookupError: unknown encoding: uft-8`。**这种错别字 Python 不会提前拦你**，要跑到那一行才知道。

---

### 字节 bytes / 字符串 str 🔶

**一句话**：**`str` 是给人看的文本，`bytes` 是给机器看的原始数据**。

```python
"中文"                  # str：3 个字符
"中文".encode("utf-8")  # bytes：6 个字节（b'\xe4\xb8\xad\xe6\x96\x87'）
len("中文")             # 2  ← 字符数
len("中文".encode("utf-8"))   # 6  ← 字节数
```

**易混**：`b"abc"` 和 `"abc"` **不是一回事**，不能混用：

```python
b"abc" + "def"      # TypeError! 字节和字符串不能相加
```

---

### JSON ✅

**一句话**：**一种通用的数据交换格式**，长得像 Python 的字典和列表。

**你的代码**：所有接口的请求体和响应体。

**JSON 支持的类型只有这些**：字符串、数字、布尔、null、数组、对象。**没有日期、没有 `Decimal`、没有自定义对象。**

**这带来一个实际后果**：Python 的 `datetime` 没法直接塞进 JSON，Pydantic 会帮你转成 ISO 格式的字符串（`"2026-09-15T19:27:22"`）。从 JSON 读回来时也是一个字符串，需要自己转回 `datetime`。

## 6.2 哈希

### 哈希 hash（密码学） ✅

**一句话**：**把任意长度的输入变成固定长度的输出，且不可逆**。

**你的代码**：

```python
# core/security.py
bcrypt.hashpw(raw, bcrypt.gensalt())     # 生成哈希
bcrypt.checkpw(raw, hashed)              # 校验
```

**三个特点**：

1. **单向** —— 从哈希推不回原文
2. **加盐** —— 同样的密码每次哈希结果不同（`gensalt()`），防止彩虹表
3. **故意慢** —— 225 毫秒一次，让暴力破解变得不可行

---

### 哈希 hash（哈希表用） 🔶

**一句话**：**把任意数据映射成一个数字，用来快速查找**。

**你的代码**：`dict` 的 key 就是靠这个。

**易混 —— ⚠️ 这跟上面那个"密码学哈希"毫无关系，只是恰好都叫 hash**：

| | 密码学哈希 | 哈希表哈希 |
| --- | --- | --- |
| 例子 | bcrypt、SHA-256 | `hash()` 内置函数 |
| 速度 | **故意慢**（225ms） | **要极快**（纳秒级） |
| 加盐 | 有 | 无 |
| 可逆 | 不可逆 | 也不需要可逆，但同样不保证唯一 |
| 用途 | 存密码、校验完整性 | 字典和集合的索引 |

**你踩过的坑就在这条上**：

```
TypeError: unhashable type: 'BookCreate'
```

字典的 key 必须"可哈希"。而 Pydantic 模型默认是不可哈希的（因为它是可变对象）。这跟密码学没关系，纯粹是"字典没法给你算下标"。

**Python 里不可哈希的类型**：`list`、`dict`、`set`。**可哈希的**：`str`、`int`、`tuple`（里面的东西也都可哈希时）。

---

### 哈希表 hash table 🔶

**一句话**：**用哈希值当索引的数据结构，查找速度接近 O(1)**。

**你的代码**：`dict`、`set`、`_users`、`_hits`。

**为什么快**：不用挨个找，而是"算一下哈希，直接跳到那个格子"。

```python
_users["alice"]      # 不用遍历，直接定位
```

**易混**：`dict` 是 Python 对哈希表的**实现**，"哈希表"是**数据结构的概念**。

---

### 字典 dict ✅ / 集合 set ⬜

**字典**：键值对。**你的代码**里到处都是。

**集合**：只有键、没有值，且自动去重。

```python
roles = {"user", "admin"}       # set
```

**易混**：`{}` 是**空字典**不是空集合！空集合要写 `set()`。这是 Python 的一个历史遗留坑。

# 第七章 并发

这一章建议整章连读，因为概念之间咬得很紧。

### 同步 sync ✅

**一句话**：**一步做完再做下一步，中间不切走**。

**你的代码**：`hash_password`、`UserRepository` 改之前的字典操作、`time.sleep`。

**易混**：同步 ≠ 慢。同步只是"执行顺序是线性的"。一段没有 IO 的纯计算代码，同步就是最快的。

---

### 异步 async ✅

**一句话**：**遇到等待时，把控制权交出去，让别人先干，等好了再回来**。

**你的代码**：所有 `async def`、所有 `await`。

**易混**：**异步 ≠ 多线程**。异步是**单线程**的 —— 它靠"一个任务等待时切去跑另一个任务"来达到"看起来同时在做"。

---

### 阻塞 blocking ✅

**一句话**：**等待的时候占着线程不放手**。

**你的代码**：

```python
time.sleep(1)          # 阻塞 1 秒，整条线程锁死
hash_password(...)     # 阻塞 225 毫秒，算 CPU
requests.get(...)      # 阻塞，等网络
```

**为什么可怕**：在 `async def` 里阻塞 = **整个服务停摆**（你第 9 周实测过：心跳 0 次）。

---

### 非阻塞 non-blocking ✅

**一句话**：**等待的时候把线程让出去**。

**你的代码**：

```python
await asyncio.sleep(1)         # 等着，但不占线程
await asyncio.to_thread(fn)    # 活儿交给别的线程，事件循环自由
await session.execute(...)     # 数据库在忙，事件循环去伺候别人
```

---

### 并发 concurrency / 并行 parallelism ⬜

**⚠️ 这两个词中文都译成"并发"或"并行"，但英文里区别很硬：**

| | 并发 concurrency | 并行 parallelism |
| --- | --- | --- |
| 定义 | **同时处理**多件事 | **同时执行**多件事 |
| 需要多核吗 | 不需要 | 需要 |
| 你的项目 | `asyncio`（一个厨师同时看几口锅） | 多进程（几个厨师各看一口锅） |

**关键区分**：并发是**任务之间交替推进**；并行是**物理上真的同时在跑**。

**你的 `to_thread` 实验为什么能变快**：因为 bcrypt 是 Rust 写的、会释放 GIL，所以多条线程**真的在不同核心上并行**。如果换成纯 Python 计算，`to_thread` 就不会变快了（GIL 挡着）。

---

### 进程 process ⬜

**一句话**：**操作系统分配资源的最小单位**。内存独立，互不干扰。

**特点**：最重、最安全（一个崩了不影响别的）、开销最大。

**你的项目**：uvicorn 的 `--workers`（第 15 周）、gunicorn。

**易混**：进程之间**不共享内存**，所以想通信要用别的手段（队列、socket、共享内存）。

---

### 线程 thread ✅

**一句话**：**进程内部的执行流**。同一进程的线程**共享内存**。

**特点**：比进程轻，但因为共享内存，会有**竞态条件**（两个线程同时改一个变量）。

**你的代码**：`asyncio.to_thread`、FastAPI 跑 `def` 路由用的 `run_in_threadpool`。

---

### 全局解释器锁 GIL ⬜

**一句话**：**CPython 的一个锁，保证同一时刻只有一个线程在执行 Python 字节码。**

**后果**：

- **多线程做纯 Python 计算不会变快** —— 因为同一时刻只有一个线程能跑 Python 代码
- **但用 C / Rust 写的库不受影响** —— 它们在干活时会**主动释放 GIL**

**你的代码**：`bcrypt` 是 Rust 写的，算哈希时释放 GIL，所以 `to_thread` 让 3 次哈希从 0.68 秒变成 0.24 秒。

**为什么它存在**：保护 Python 内部数据结构的完整性，让 CPython 的实现简单很多。代价就是多线程算不快。

**易混**：GIL 是 **CPython 这个实现**的特性，不是 Python 语言的规范。Jython、PyPy 没有 GIL。

---

### 协程 coroutine ✅

**一句话**：**可以暂停和恢复的函数**。用 `async def` 定义。

**你的代码**：所有 `async def` 函数。

**三个必须记住的点**：

1. **`async def` 定义的函数，调用它不会执行函数体**，只会返回一个协程对象。要执行必须 `await` 它。
2. **协程的切换点是 `await`**。没有 `await` 的协程一旦被调度，就会一口气跑到底。
3. **协程的调度者是事件循环**，不是操作系统。

---

### 事件循环 event loop ✅

**一句话**：**一个"待办队列 + 一个无限循环"，负责把协程一个个拎出来跑**。

**它的核心逻辑（伪代码）**：

```python
while True:
    for task in ready_queue:      # 把队列里所有能跑的跑一遍
        task.run_until_await()    # 跑到下一个 await 就停
    sleep_until_next_timer()      # 没事干就等到最近一个定时器到点
```

**你的代码**：`asyncio.run(main())` 会建一个事件循环，跑完 `main` 再关掉它。

**三个关键认知**（第 9 周反复讲的）：

1. **一条线程上，任何时刻只有一个东西在跑。**
2. **`create_task` 只是登记，不交权；`await` 才交权。**
3. **只有事件循环拿到线程，队列里的东西才能被跑。**

---

### 任务 Task / 未来 Future ✅

**一句话**：`Task` 是"已经登记到事件循环上的协程"；`Future` 是"将来会有值"的占位符。

**你的代码**：

```python
task_a = asyncio.create_task(job("A", 1.0))     # Task
task_a.done()                                    # 查它好了没
await task_a                                     # 取结果
```

**易混**：`create_task` 返回的是**取件凭证**，不是结果本身。你拿到的不是货，是一张写着"正在做，好了凭这张单子来取"的凭条。

---

### `await` ✅

**一句话**：**停在这一行，把线程让出去，直到我等的东西结束再回来。**

**三个必须分清的层次**：

| 写法 | 启动？ | 等待？ | 调用者停吗 |
| --- | --- | --- | --- |
| `await coro` | 是 | 是 | **停** |
| `asyncio.create_task(coro)` | 是（登记） | 否 | **不停** |
| `await asyncio.gather(a, b)` | 一批 | 一批 | **停** |

**易混 —— `await` 的等待时间是"它还需要多久"**，不是"固定要等多久"。如果你 await 的东西已经完成了，`await` **立刻返回**。

---

### `asyncio.gather` ✅

**一句话**：**批量启动 + 批量收结果**。

**你的代码**：

```python
await asyncio.gather(*(fake_async_hash(f"假{i}") for i in range(3)))
```

**两个必须知道的行为**：

1. **结果按你传入的顺序返回**，不是按完成顺序。
2. **一个任务抛异常，gather 立刻把异常抛给你，但其他任务不会被取消**，会在后台继续跑完。

**易混**：`gather` **不是并发的来源**。它只负责"启动"和"收集"，能不能真并发，取决于被包起来的协程里**有没有 `await`**。

---

### 线程池 · 执行器 executor ✅

**一句话**：**一组预先创建好的线程，反复用来跑任务**，避免每次新建线程的开销。

**你的项目里有两个池子，各有各的上限**：

| 谁在用 | 池子 | 你这台机器上的上限 |
| --- | --- | --- |
| `asyncio.to_thread` | asyncio 默认执行器 | `min(32, CPU核数+4)` = 16 |
| FastAPI 跑 `def` 路由 | anyio 的线程池 | 固定 40 |

**易混 —— 这是两个独立的池子，不共享、不互借。**

**为什么这个数字重要**：**外包 ≠ 无限扩容**。第 17 个 `to_thread` 请求就得排队等线程。

---

### `to_thread` ✅

**一句话**：**把同步的阻塞函数丢到线程池去跑**。

**你的代码**：

```python
"password": await asyncio.to_thread(hash_password, user.password),
```

**写法规则**：第一个参数是**函数本身**，后面依次跟它的参数。

**第 11 周的调整**：`to_thread` 的位置从**路由层**挪到了**服务层**，从"包住整个服务调用"变成"精确包住那一次哈希运算"。

**为什么**：`to_thread` 只能跑同步函数，而现在 `service.register` 是协程函数，塞进 `to_thread` 会得到一个没人 await 的协程对象。而且从设计上说，**`to_thread` 应该包住"最小的阻塞单元"**。

---

### 上下文切换 context switch ⬜

**一句话**：**从一个执行流换到另一个执行流。**

**三个层次的切换成本**：进程切换 > 线程切换 > 协程切换。

**为什么协程这么轻**：协程的切换**不经过操作系统** —— 它是事件循环在用户态自己做的，只是保存几个变量。这也是为什么一台机器能跑几万个协程，却跑不了几万个线程。

### 响应 response ✅

**一句话**：**服务端发回去的一坨东西**。

**它的组成**：

    ↓ 编码
字节
    ↓ 加上状态码和响应头
HTTP 响应
```

### 路由 route ✅

**一句话**：**"什么样的请求交给哪个函数处理"这条规则。**

**你的代码**：

```

这一行的意思是：**"路径匹配 `/users/xxx` 且方法是 GET 的请求，交给下面的函数"**。

---

### 端点 endpoint ✅

**一句话**：**那个被路由指向的函数本身。**

**你的代码**：`get_user`、`register_user`、`login` 这些函数就是端点。

**易混 —— 路由 vs 端点**：

- **路由**是规则（地图上的一条线）
- **端点**是终点（线的尽头那个地方）

日常说话里两个词经常混用（"这个路由返回什么"其实问的是端点）。严格区分的话：`/users/{username}` 是**路由**，`get_user` 是**端点**。

---

### 路径参数 path params ✅

**一句话**：**嵌在路径里的变量**。

**你的代码**：

```python

async def get_user(user_data: PathUserDep):
```

访问 `/users/alice` 时，`username` 就是 `"alice"`。

**特点**：**它是资源身份的一部分**。`/users/alice` 和 `/users/bob` 是两个不同的资源。

### 查询参数 query params ✅

**一句话**：**URL 里 `?` 后面那些**，用来筛选、排序、分页。

**你的代码**：

class Pagination:

        self,

```

访问 `/users/?page=2&size=5`。

**易混 —— 路径参数 vs 查询参数**：

| | 路径参数 | 查询参数 |
| --- | --- | --- |
| 例子 | `/users/alice` | `/users/?page=2` |
| 作用 | 指定**哪个**资源 | 给资源**加条件** |
| 必填 | 通常是 | 通常有默认值 |

**判断标准**：**如果去掉它这个 URL 就没意义了，它是路径参数；如果去掉它还能返回一个合理结果（只是范围变大），它是查询参数。**

### 请求体 body ✅

**一句话**：**请求里携带的主体数据**，主要是 POST/PUT/PATCH 用。

**你的代码**：

#                        ^^^^^^^^^^^^^^ FastAPI 从请求体里解析出这个
```

**易混 —— 数据可以放在四个地方**：

| 位置 | FastAPI 里怎么接 |
| --- | --- |

---

### 请求头 header ✅

**一句话**：**请求/响应的元信息** —— 认证、内容类型、缓存策略等。

**你的代码**：

```python
request.headers.get("x-request-id")          # 读取客户端传来的请求 ID
response.headers["X-Request-ID"] = ...        # 写回一个
authorization: Bearer eyJhbGci...             # OAuth2 的 token 就在这儿
```

**易混**：请求头名**不区分大小写**。`Content-Type`、`content-type`、`CONTENT-TYPE` 是同一个。Python 里读的时候统一用小写最省事。

---

### 状态码 status code ✅

**一句话**：**一个三位数，快速说明这次请求的结果。**

| 范围 | 含义 | 你项目里的例子 |
| --- | --- | --- |
| 2xx | 成功 | 200 查询成功、201 创建成功、204 删除成功无内容 |
| 3xx | 重定向 | （没用） |
| 4xx | **客户端**的错 | 400 参数错、401 未认证、403 无权限、404 不存在、409 冲突、422 校验失败、429 太频繁 |
| 5xx | **服务端**的错 | 500 服务器内部错误 |

**易混 —— 401 vs 403，这是最经典的一组**：

- **401 Unauthorized** 名字有误导性，实际意思是"**你没证明你是谁**" → 请去登录
- **403 Forbidden** 意思是"**我知道你是谁，但你没资格**" → 登录也没用

你的代码里 `InvalidCredentials` 是 401（带 `WWW-Authenticate: Bearer` 头），`require_role` 抛的是 403。

**记法**：**401 = "你是谁？" 403 = "我认识你，但不行。"**

### HTTP 方法 ✅

| 方法 | 语义 | 幂等？ |
| --- | --- | --- |
| GET | 查 | 是 |
| POST | 创建 | **否** |
| PUT | 整体替换 | 是 |
| PATCH | 部分更新 | 否（通常） |
| DELETE | 删 | 是 |

**幂等 idempotent ⬜**：**同一个请求做一次和做一百次，结果一样。**

**为什么重要**：网络会重试。如果 `POST /users/register/` 被重试了，就可能注册出两个用户（或者第二个报 409）。而 `DELETE /users/alice` 重试多少次结果都是"alice 没了"。

**注意**：幂等说的是"**结果**一样"，不是"返回的状态码一样"。`DELETE` 第一次返回 204，第二次返回 404，但它仍然是幂等的 —— 因为**服务端的状态**没变。

```
GET    /books/          查列表
GET    /books/{isbn}    查一个
POST   /books/          创建一个
PATCH  /books/{isbn}    改一个
DELETE /books/{isbn}    删一个
```

### 中间件 middleware ✅

**一句话**：**夹在"请求进来"和"响应出去"之间的一层处理逻辑**。

**你的代码**：

```python
@app.middleware("http")
async def add_request_id(request: Request, call_next):
    request_id = request.headers.get("x-request-id") or uuid.uuid4().hex
    request.state.request_id = request_id
    response = await call_next(request)         # ← 交给下一层
    response.headers["X-Request-ID"] = request_id
    return response
```

**洋葱模型**：

```
请求 →
  第一层中间件（前半段）
    第二层中间件（前半段）
      路由函数
    第二层中间件（后半段）
  第一层中间件（后半段）
← 响应
```

**`call_next` 就是"往里面走一层"**。你可以在它前面做事（改请求）、在它后面做事（改响应）、甚至不调它直接返回（短路）。

**易混 —— 中间件 vs 依赖**：

| | 中间件 | 依赖 |
| --- | --- | --- |
| 作用范围 | **所有**请求 | 只有声明了它的路由 |
| 能改响应 | 能 | 基本不能 |
| 拿到路由信息 | 拿不到（不知道最后匹配哪个函数） | 知道 |
| 你的用途 | 请求 ID、日志、CORS | 认证、限流、分页 |

**判断标准**：**需要在"进路由之前"就生效、或者需要改响应的 → 中间件。知道具体是哪个接口、要读路径参数的 → 依赖。**

### CORS 🔶

**一句话**：**浏览器的安全策略** —— 默认禁止网页访问**不同源**的接口，需要服务端显式放行。

**同源** = 协议 + 域名 + 端口 三者完全相同。

`http://localhost:5173`（前端）访问 `http://localhost:8000`（后端）**跨源了**，因为端口不同。

**你的代码**：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://127.0.0.1:5173"],
    allow_headers=["*"],
)
```

**易混**：CORS 是**浏览器**的限制，不是服务器的。用 `curl` 或 Postman 发请求**完全不受 CORS 影响**。所以"CORS 报错"永远只在前端出现。

### 认证 authentication / 授权 authorization ✅

**一句话**：**认证 = 你是谁；授权 = 你能干什么。**

**你的代码**：

| | 你项目里的实现 |
| --- | --- |
| 认证 | `POST /token` + `get_caller`（解 JWT，查出用户） |
| 授权 | `require_role(ROLE_ADMIN)`、`require_self_or_admin` |

**记法**：**认证在前，授权在后**。没认证就没法授权 —— 你总得先知道是谁，才能判断他能干什么。

### Token / JWT / OAuth2 ✅

**Token**：**一张通行证**。客户端登录后拿到它，之后每次请求带着它，服务端就能认出你。

**JWT**（JSON Web Token）：**一种具体的 token 格式** —— 三段用点分隔的字符串：

```
eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiJhbGljZSIsImV4cCI6MTc2ODU4Mw . dBjftJeZ4CVP...
      头部                     载荷（数据）                        签名
```

**关键认知**：**载荷是"编码"过的，不是"加密"过的**。任何人 base64 解开都能看到里面的内容（`sub`、`exp`）。签名保证的是**没被篡改**，不是**保密**。

所以 JWT 里**绝不能放密码**。

**你的代码**：

```python
decode_access_token(token)                       # 验签 + 检查 exp
options={"require": ["exp", "sub"]}              # 强制要求这两个字段存在
```

**OAuth2**：一套**授权框架**，不是具体的 token 格式。你的 `POST /token` 用的是其中的"密码流"。

**易混 —— OAuth2 vs JWT**：它们不是一回事。OAuth2 规定"怎么拿到 token"，JWT 规定"token 长什么样"。你的项目里两个都用上了。

**你的项目没有用它** —— 你用的是 JWT，状态全在客户端那边。

**意思三：泛指** —— "一次对话"。

**怎么分辨**：看上下文。提到"事务""提交""连接池"就是意思一；提到 "cookie"、"服务端存储" 就是意思二。

### 限流 rate limiting ✅

**一句话**：**限制一段时间内某个来源能发多少请求**。

**你的代码**：

```python
def rate_limiter(scope: str, times: int, window: int):
    async def limiter(request: Request) -> None:
        key = f"{scope}:{client}"
        timestamps = _hits.setdefault(key, [])
        cutoff = now - window
        while timestamps and timestamps[0] < cutoff:
            timestamps.pop(0)               # 滑出窗口的删掉
        if len(timestamps) >= times:
            raise HTTPException(status_code=429, detail="请求过于频繁，请稍后再试")
        timestamps.append(now)
    return limiter
```

**这是"滑动窗口"算法** —— 只看最近 `window` 秒内有多少次请求。

**易混**：`_hits` 是**内存字典**，所以：
- 进程重启就清零
- 多个 worker 进程各算各的（第 12 周会用 Redis 解决）

### 数据库 database / DBMS ⬜

**数据库**是数据的集合，**DBMS** 是管理它的软件（SQLite、PostgreSQL、MySQL）。

**你的项目**：SQLite（第 10 周起）。

### SQL 🔶

**一句话**：**和关系型数据库对话的语言。**

**你的代码**：

```python
text("SELECT 1")
text("SELECT COUNT(*) FROM users")
text("SELECT profile FROM users WHERE username = 'bob'")
```

**易混 —— SQL 分两种**：

| | 全称 | 干什么 | 例子 |
| --- | --- | --- | --- |
| DDL | Data **Definition** Language | 定义结构 | `CREATE TABLE`、`ALTER TABLE` |
| DML | Data **Manipulation** Language | 操作数据 | `SELECT`、`INSERT`、`UPDATE`、`DELETE` |

你的 `Base.metadata.create_all` 产生的是 DDL，ORM 的增删改查产生的是 DML。

### 表 table / 行 row / 列 column ✅

**一句话**：**表是二维表格，行是一条记录，列是一个字段。**

```
        username   email              role
        ─────────  ─────────────────  ──────
row 1   admin      admin@example.com  admin
row 2   alice      alice@example.com  user
        ↑
      column
```

**易混 —— 同一个东西在两个世界里的叫法**：

| 数据库世界 | Python 世界 |
| --- | --- |
| 表 table | 类 class（`User`） |
| 行 row | 实例 instance |
| 列 column | 属性 attribute |

**这张对照表就是 ORM 存在的全部理由** —— 它负责在这两套词汇之间来回翻译。

### 主键 primary key ✅

**一句话**：**能唯一标识一行的那一列（或几列）。**

**你的代码**：

```python
username: Mapped[str] = mapped_column(String(20), primary_key=True)
isbn: Mapped[str] = mapped_column(String(13), primary_key=True)
```

**特点**：不能重复、不能为空。

**易混**：主键是**业务上的唯一标识**，不是"必须有个 id 列"。你的 `User` 用 `username` 当主键，`Book` 用 `isbn` —— 都很合理。

**另一种常见做法**是加一个自增的 `id` 当主键，业务字段加唯一约束。好处是"业务字段可以改"（用户能改名，但主键不该变）。

### 外键 foreign key ⬜

**一句话**：**指向另一张表主键的列**，用来表达表之间的关系。

```sql
CREATE TABLE borrows (
    id INTEGER PRIMARY KEY,
    username TEXT REFERENCES users(username),    ← 外键
    isbn TEXT REFERENCES books(isbn)
);
```

**你的项目还没有外键** —— 目前两张表互不相干。如果要记录"谁借了哪本书"，就需要一张借阅表，里面两个外键。

---

### 唯一约束 unique constraint ✅

**一句话**：**这一列的值不能重复。**

**你的代码**：

```python
email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
```

**易混 —— 它和应用层查重是两道独立的防线**：

- **应用层查重**（`repo.exists_email`）是为了给用户**友好的错误信息**
- **数据库唯一约束**是为了在**并发下保证数据正确**

两个请求同时通过了应用层查重时，只有数据库能拦住第二个。**两道都要有。**

---

### 索引 index ✅

**一句话**：**给某一列建一本"目录"，让按它查询变快。**

**你的代码**：

```python
email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
```

**代价**：索引占空间，而且每次写入都要更新索引。**所以不要给每一列都加索引** —— 只给经常用来查询的列加。

**易混**：主键**自动**有索引。`unique=True` 也会自动创建唯一索引，所以严格说 `unique=True` 和 `index=True` 同时写有点冗余（但无害，意图更明确）。

### 事务 transaction / ACID ⬜

**一句话**：**一组操作，要么全成，要么全败。**

**你的代码**：

```python
async with engine.begin() as conn:      # 开一个事务
    await conn.run_sync(Base.metadata.create_all)
# 走出这个块 → 自动 COMMIT；抛异常 → 自动 ROLLBACK
```

**ACID** 是事务的四个保证：

| 字母 | 含义 |
| --- | --- |
| **A** 原子性 | 全成或全败 |
| **C** 一致性 | 事务前后数据都符合约束 |
| **I** 隔离性 | 并发事务互不干扰 |
| **D** 持久性 | 提交了就真的存住了 |

**易混 —— 事务的边界应该划在哪，是有讲究的**。第 11 周你的仓储层选择"一个方法一个事务"，好处是简单，代价是**跨方法的原子性没了**（`borrow` 的读-改两步之间可能被插队）。

---

### 提交 commit / 回滚 rollback ✅

**一句话**：**提交 = 确认这些改动；回滚 = 撤销这些改动。**

**你的代码**：

```python
session.add(user)          # 只是挂在会话上，数据库里还没发生
await session.commit()      # ← 这一刻才真正写进去
```

**易混 —— `add` 和 `commit` 是两件事**：`add` 只记账，`commit` 才发货。

**回滚**：`async with` 块里抛异常时自动回滚，或者手动 `await session.rollback()`。

---

### 连接 connection / 连接池 connection pool ✅

**一句话**：**连接是"和数据库之间的一条通道"；连接池是"预先开好一批通道，反复复用"。**

**为什么要池**：建立数据库连接很贵（TCP 握手、认证、初始化）。如果每个请求都新建一条，性能会烂得没法看。

**你的项目**：

```python
engine = create_async_engine(settings.DATABASE_URL, echo=settings.DEBUG)
```

引擎内部就管着一个连接池。

**两种池子的区别**（第 10 周你踩过这个）：

| 池子 | 特点 | 什么时候用 |
| --- | --- | --- |
| `StaticPool` | **只有一条连接，谁要都给这条** | SQLite 内存库 |
| `AsyncAdaptedQueuePool` | 多条连接，会缓存复用 | SQLite 文件库（默认） |

**为什么这个区别重要**：连接是**绑定在创建它的事件循环上**的。测试里每个 `TestClient` 都会新建一个事件循环，如果连接被池子缓存下来跨测试复用，就会报 `attached to a different loop`。

### 驱动 driver ✅

**一句话**：**真正和数据库说话的那一层。**

| 数据库 | 同步驱动 | 异步驱动 |
| --- | --- | --- |
| SQLite | `sqlite3` | **`aiosqlite`** |
| PostgreSQL | `psycopg2` | **`asyncpg`** |
| MySQL | `pymysql` | `aiomysql` |

**易混 —— 异步驱动的选择直接决定你会不会踩"假异步"**。用 `psycopg2` 就是在 `async def` 里阻塞，第 9 周那个"心跳 0 次"的悲剧会在数据库上重演，而且更频繁。

### 引擎 engine ✅ / 方言 dialect ⬜

**引擎**：SQLAlchemy 的**连接池管理员**。

**方言 dialect**：SQLAlchemy 内部"针对某个具体数据库的适配层"。

**你的代码**：`sqlite+aiosqlite:///./app.db` 里的 `sqlite` 是方言，`aiosqlite` 是驱动。

**方言存在的意义**：你写的 `select(User)` 会被编译成不同数据库认识的 SQL。**换数据库时改的只是 URL**，Python 代码一行不用动。

### ORM ✅

**一句话**：**Object-Relational Mapping，对象-关系映射** —— 把数据库的表映射成 Python 的类。

**核心价值**是那张对照表（见「表/行/列」）：

```python
user = await session.get(User, "alice")    # 数据库的行 → Python 对象
user.email = "new@example.com"             # 改属性
await session.commit()                      # 自动生成 UPDATE 语句
```

**易混 —— ORM 不是必须的**：

```python
await session.execute(text("SELECT * FROM users WHERE username = 'alice'"))
```

纯 SQL 也能用。ORM 的价值在**类型安全、防止 SQL 注入、让代码和数据结构解耦**；代价是**多一层抽象，有时会生成低效的 SQL**（比如 N+1 问题）。

**你的项目两种都用**：业务代码走 ORM，健康检查和交叉验证用裸 SQL。

### 模型 model ⚠️ 一词多义

**⚠️ 这个词在你的项目里有三个意思：**

**意思一：Pydantic 模型**（`schemas/`）—— 管 **API 出入的形状**。

```python
class UserCreate(BaseModel):
    username: str = Field(..., min_length=3, max_length=20)
```

**意思二：ORM 模型**（`models/`）—— 管 **数据库表的形状**。

```python
class User(Base):
    __tablename__ = "users"
    username: Mapped[str] = mapped_column(String(20), primary_key=True)
```

**意思三：泛称** —— 任何"对现实的简化表示"。

**为什么它们不能合并**：`UserCreate` 有 `password` 但 `UserResponse` 没有；`Book` 模型有 `internal_note` 但 `BookResponse` 没有。

> **数据库存的是完整事实，API 暴露的是筛选后的视图。**

### 迁移 migration ⬜

**一句话**：**"改表结构"这件事的版本管理。**

**为什么需要它**：`create_all` 只会建**缺失的表**，它**不会改已有的表**。你要给 `users` 加一列，`create_all` 无能为力。

**怎么做**：写一个迁移脚本（`.py` 文件），里面写清楚"升级要执行什么 SQL，降级要执行什么 SQL"。然后用工具（Alembic）按顺序执行它们。

**你的项目**：第 11 周引入 Alembic。

**易混**：迁移不是"重新建表"。它是**增量修改** —— 生产环境有真实数据，你不能删库重建。

### N+1 查询问题 ⬜

**一句话**：**本该 1 次查询搞定的事，被 ORM 拆成了 1 + N 次。**

```python
books = await session.execute(select(Book))     # 1 次查询
for book in books:
    print(book.author.name)      # 每个 book 又查一次 → N 次
```

总共 1 + N 次数据库往返。数据量大时性能会崩。

**修法**：用 `selectinload` / `joinedload` 一次性把关联数据带出来。

**你的项目暂时没有关联关系，所以碰不到。** 一旦第 11 周加了借阅记录表，就要留意了。

### 夹具 fixture ✅

**一句话**：**测试的"依赖注入"** —— 把测试需要的前置条件抽出来复用。

**你的代码**：

```python
@pytest.fixture(autouse=True)
def clean_state():
    _users.clear(); _books.clear(); _hits.clear()
    yield
    _users.clear(); _books.clear(); _hits.clear()

@pytest.fixture
def auth_client(client):
    seed_user("caller", ROLE_USER)
    ...
```

**易混**：`yield` 之前的代码是"准备"，之后的代码是"清理" —— 和第 5 周学的 `yield` 依赖是**同一个机制**。

**`autouse=True`** 意思是"每个测试都自动用，不用写在参数里"。

### 测试隔离 test isolation ✅

**一句话**：**每个测试都在干净的环境里跑，互不影响。**

**你的代码**：`clean_state` 那个 autouse fixture。

**为什么重要**：如果测试 A 留下的数据影响了测试 B，你会得到"单独跑能过、一起跑就挂"的结果 —— 这种问题极难排查。

**第 11 周的变化**：数据从内存字典搬进数据库后，`clean_state` 那套就失效了，需要换成"每个测试一个独立的测试数据库"。

### 桩 stub / 模拟 mock ⬜

**一句话**：**测试时用一个假的实现替换真的。**

- **桩 stub**：只提供固定的返回值
- **模拟 mock**：还能记录"你调用了我几次、传了什么参数"

**易混**：你的项目里**一个都没有** —— 这是故意的。第 7 周你用的是"真 token、真 bcrypt、真 TestClient"，因为这些东西都足够快、足够确定。**能用真的就用真的**，mock 是不得已才用的。

### 覆盖率 coverage ⬜

**一句话**：**测试执行到的代码占总代码的比例。**

**易混 —— 覆盖率是参考，不是目标**：100% 覆盖率不代表测试有效（可能每个断言都是空的），60% 覆盖率也可能抓到所有关键 bug。**它衡量的是"没测到多少"，不是"测得多好"。**

# 第十一章 工程与运维

### 环境变量 environment variable ✅

**一句话**：**操作系统层面的键值对**，程序启动时能读到。

**你的代码**：`.env` 文件里的 `SECRET_KEY`、`DATABASE_URL`。

**为什么用它**：**让配置和代码分开**。

- 数据库地址在开发机和生产机上不一样 → 不能写死在代码里
- 密钥绝不能提交到 git → 必须从外面注入

**易混 —— `.env` 文件只是一种"开发时的便利"**：生产环境通常由容器编排或云平台直接注入环境变量，不会有 `.env` 文件。

**三条铁律**（你在第 4 周和第 10 周都验证过）：

1. `.env` 必须在 `.gitignore` 里
2. `.env.example` 提交，里面只放占位符
3. 忽略规则要写 `.env*` 而不是 `.env` —— 否则云同步产生的冲突副本会带着密钥被提交

---

### 配置 config ✅

**一句话**：**程序运行时可调整的参数。**

**你的代码**：

```python
class Settings(BaseSettings):
    APP_NAME: str = "FastAPI App"
    DEBUG: bool = False
    DATABASE_URL: str
    SECRET_KEY: str
    model_config = SettingsConfigDict(env_file=".env", case_sensitive=False)

@lru_cache
def get_settings() -> Settings:
    return Settings()
```

**易混 —— 配置 vs 常量**：

- **常量**：写在代码里、永远不变（`ROLE_ADMIN = "admin"`）
- **配置**：随环境变化（数据库地址、密钥、调试开关）

**`@lru_cache` 的作用**：让 `Settings()` 只被构造一次，之后都返回同一个对象。这叫**单例**。

# 第十二章 ⚠️ 最容易搞混的词：一词多义

这一章单独列出来，因为你已经踩过其中的坑了。

**遇到下面任何一个词，先问一句："现在说的是哪个语境下的？"** 这比背定义有用得多。

| 词 | 含义一 | 含义二 | 含义三 |
| --- | --- | --- | --- |
| **模型 model** | Pydantic 模型（API 形状） | ORM 模型（表结构） | 泛称"简化表示" |
| **会话 session** | SQLAlchemy 的（数据库工作台） | HTTP session（浏览器会话） | 泛指"一次对话" |
| **哈希 hash** | 密码学哈希（bcrypt，慢、加盐） | 哈希表哈希（`hash()`，快） | —— |
| **上下文 context** | `async with`（资源进出） | `request.state`（请求级共享数据） | LLM 的上下文 |
| **依赖 dependency** | 代码依赖（`Service` 需要 `Repo`） | FastAPI 的 `Depends` | 第三方库依赖 |
| **接口 interface** | API 接口（HTTP 端点） | 编程的"接口"（一组方法约定） | 硬件的物理接口 |
| **引擎 engine** | SQLAlchemy 的连接池管理员 | 数据库引擎（SQLite/InnoDB） | —— |
| **驱动 driver** | 数据库驱动（aiosqlite） | 硬件驱动 | —— |
| **池 pool** | 连接池 | 线程池 | 内存池 |
| **管道 / 过程** | —— | —— | —— |

**最后一条建议**：**听到一个术语觉得别扭时，大概率是"词没错，语境不对"。** 这时候不要怀疑自己的理解能力，先确认对方在说哪一层。

# 第十三章 串联：一个注册请求的完整旅程

把前面所有词串成一条线，你会看到它们**不是孤立的知识点，而是一条流水线上的工位**。

**场景**：前端在 `http://localhost:5173` 发起注册，请求 `POST http://localhost:8000/users/register/`，请求体是 `{"username": "carol", ...}`。

```
① 【客户端】浏览器
   fetch(...) 带着 JSON 字符串
   ↓
② 【网络】编码成字节，通过 套接字 socket 发出去
   ↓
③ 【服务器】uvicorn 监听在 8000 端口
   收到字节 → 解码 → 按 ASGI 协议交给 FastAPI
   ↓
④ 【中间件】洋葱从外往里剥
   CORSMiddleware：检查来源 localhost:5173 在不在白名单
   add_request_id：生成一个 request_id，塞进 request.state
   log_requests：记下开始时间
   ↓
⑤ 【路由匹配】FastAPI 查路由表
   POST + /users/register/  →  匹配到端点函数 register_user
   ↓
⑥ 【依赖解析】FastAPI 开始装配这个端点需要的一切
   get_session      → 从连接池借一条连接，包成 AsyncSession
   users_rate_limit → 闭包造出来的限流器，检查请求频率
   register_rate_limit → 另一个限流器
   get_user_repo    → 拿着 session 造出 UserRepository 实例
   get_user_service → 拿着 repo 造出 UserService 实例
   （同一个请求里 get_session 只会被调用一次 —— 依赖缓存）
   ↓
⑦ 【反序列化】解析请求体
   JSON 字节 → 解码 → 字典 → Pydantic 校验 → UserCreate 实例
   校验失败？→ RequestValidationError → 全局处理器 → 422
   ↓
⑧ 【端点函数】await service.register(user)
   ↓
⑨ 【服务层】业务规则
   先 await repo.exists(username)        查重名
   再 await repo.exists_email(email)     查邮箱
   再 await asyncio.to_thread(hash_password, ...)   ← bcrypt 阻塞 225ms，
                                                      外包给线程池
   组装成一个 dict
   await repo.create(...)
   ↓
⑩ 【仓储层】翻译 + 落库
   把 dict 变成 ORM 对象：User(**data)
   session.add(user)        挂到工作台上
   await session.commit()   生成 INSERT，交给连接，写进 SQLite
   把 ORM 对象翻译回 dict 返回
   ↓
⑪ 【返回路上】原路返回
   dict → 按 response_model 校验 → 序列化 → JSON 字符串
   → 编码成字节 → 交给 uvicorn
   ↓
⑫ 【中间件后半段】洋葱往外剥
   log_requests：算出耗时，加一个 X-Process-Time-Ms 头，打印日志
   add_request_id：把 request_id 加到响应头
   CORSMiddleware：加上 Access-Control-Allow-Origin
   ↓
⑬ 【响应】uvicorn 通过 socket 把字节发回浏览器
   ↓
⑭ 【依赖清理】响应发出之后
   会话关闭，连接还给池子
   ↓
⑮ 【客户端】浏览器收到 201
   CORS 检查通过 → 前端拿到 JSON
```

**在这条链上，每一站的"术语"分别是**：

| 阶段 | 涉及的术语 |
| --- | --- |
| ① ② | 请求、JSON、序列化、编码、字节、套接字 |
| ③ | 进程、线程、事件循环、ASGI |
| ④ | 中间件、CORS、请求头、上下文 |
| ⑤ | 路由、端点、路径参数 |
| ⑥ | 依赖、依赖注入、控制反转、闭包、装饰器、连接池、会话 |
| ⑦ | 反序列化、模型、类型注解、异常 |
| ⑧ ⑨ | 协程、异步、await、阻塞、非阻塞、to_thread、线程池 |
| ⑩ | ORM、仓储、模型、事务、提交、SQL、驱动、方言 |
| ⑪ | 序列化、响应、状态码 |
| ⑭ | 上下文管理器、生成器、`yield`、清理 |
