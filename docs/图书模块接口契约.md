# 图书模块接口契约

> 这份文档描述"接口对外长什么样"。它不规定你内部怎么分层。
> 前端、测试、文档都按这份契约来，所以**它是唯一的事实来源**。

---

## 怎么读这份文档

同一份文档要**读四遍**，每遍找不同的东西：

| 第几遍 | 找什么 | 写进哪个文件 |
|---|---|---|
| 第 1 遍 | 字段名、类型、约束 | `schemas/book.py` |
| 第 2 遍 | 路径、方法、状态码、错误 | `api/routers/book.py` |
| 第 3 遍 | 业务规则（能不能重复、能不能借） | `services/book_service.py` |
| 第 4 遍 | 怎么存、按什么查 | `repositories/book_repo.py` |

**同一份需求单，四个文件各取所需。** 这就是分层在实际工作中的样子。

---

## 一、公共字段字典

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `isbn` | string | **13 位纯数字** | 唯一标识，不能重复 |
| `title` | string | 1-100 字符 | 书名 |
| `author` | string | 1-50 字符 | 作者 |
| `price` | number | **必须 > 0** | 价格 |
| `stock` | integer | **必须 >= 0** | 库存 |
| `internal_note` | string \| null | 最长 200 字符，**可不传** | 内部备注 |

---

## 二、三个模型的字段归属

| 模型 | 用途 | 包含字段 |
|---|---|---|
| `BookCreate` | 新增时的请求体 | `isbn`、`title`、`author`、`price`、`stock` 全部**必填**；`internal_note` **可选** |
| `BookResponse` | 所有成功响应 | `isbn`、`title`、`author`、`price`、`stock`（**没有 `internal_note`**） |
| `BookUpdate` | PATCH 的请求体 | `title`、`author`、`price`、`stock`、`internal_note` **全部可选** |

---

## 三、六个接口的请求 / 响应

### 1. `POST /books/` 新增图书

**请求体：**

```json
{
  "isbn": "9787115428028",
  "title": "流畅的Python",
  "author": "Luciano Ramalho",
  "price": 139.0,
  "stock": 5,
  "internal_note": "2024-01 第三次印刷"
}
```

**成功 201：**

```json
{
  "isbn": "9787115428028",
  "title": "流畅的Python",
  "author": "Luciano Ramalho",
  "price": 139.0,
  "stock": 5
}
```

**失败 409**：`{"detail": "ISBN 已存在"}`

### 2. `GET /books/` 图书列表

**成功 200：** 图书对象的数组

```json
[
  {
    "isbn": "9787115428028",
    "title": "流畅的Python",
    "author": "Luciano Ramalho",
    "price": 139.0,
    "stock": 5
  }
]
```

### 3. `GET /books/{isbn}` 图书详情

**成功 200：** 单个图书对象（同上格式）

**失败 404**：`{"detail": "图书'9787115428028'不存在"}`

### 4. `PATCH /books/{isbn}` 修改图书

**请求体**（只传要改的字段，没传的不要动）：

```json
{"price": 129.0, "stock": 3}
```

**成功 200：** 修改后的完整图书对象

**失败 404**：同接口 3

### 5. `DELETE /books/{isbn}` 删除图书

**成功 204：** 无响应体

**失败 404**：同接口 3

### 6. `POST /books/{isbn}/borrow` 借出

**请求体：** **没有请求体**（只有路径里的 isbn）

**成功 200：** 借出后的图书对象，`stock` 已减 1

**失败 404**：图书不存在

**失败 400**：`{"detail": "库存不足"}`

## 四、约束 → Pydantic 写法对照

| 契约里的约束 | Pydantic 里的写法 |
|---|---|
| 13 位纯数字 | `Field(..., pattern=r"^\d{13}$")` |
| 1-100 字符 | `Field(..., min_length=1, max_length=100)` |
| 1-50 字符 | `Field(..., min_length=1, max_length=50)` |
| 必须 > 0 | `Field(..., gt=0)` |
| 必须 >= 0 | `Field(..., ge=0)` |
| 最长 200，可不传 | `Field(None, max_length=200)` |
| 全部可选（PATCH 用） | `Field(None, ...)`，类型写 `str \| None` / `float \| None` |

---

## 五、四个容易漏的点

1. **所有成功响应里都不能出现 `internal_note`**——包括列表、详情、新增、PATCH、借出。
2. **`borrow` 没有请求体**，所以它的路由函数签名里不该有 Pydantic 模型参数。
3. **`BookUpdate` 的字段全部可选**，配合 `model_dump(exclude_unset=True)` 使用。
4. **404 的 `detail` 里要带上 isbn**，方便前端定位是哪个资源没找到。
