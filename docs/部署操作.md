## 一、首次准备（只做一次）

### ① 在 NAS 上打开 SSH

**飞牛桌面 → 设置 / 控制面板 → 找 "SSH" 或 "远程访问" → 打开。**

**同时记下 NAS 的 IP**（在飞牛的网络设置里看）。

---

### ② 在你自己的电脑（PowerShell）—— 连上 NAS

```powershell
ssh li@192.168.222.233
```

- 第一次会问 `Are you sure you want to continue connecting?` → 输入 `yes` 回车
- 然后输 NAS 的登录密码（**输入时不显示，正常现象**）

**连上后提示符变成 NAS 的样子。** 从这里开始的命令都在**这个 SSH 窗口**里跑。

---

### ③ 在 NAS 的 SSH 窗口 —— 检查环境

```bash
docker --version
git --version
```

**两条都能打印版本号 → 继续。**

- `docker` 没有 → 飞牛应用中心里装 Docker
- `git` 没有 → 见「兜底」一节

---

### ④ 在 NAS 的 SSH 窗口 —— 把代码拉下来

```bash
cd ~
git clone https://github.com/lds250250/FastAPI_learning.git
cd FastAPI_learning
ls
```

**`ls` 应该能看到 `Dockerfile`、`pyproject.toml`、`uv.lock`、`src`、`tests`。**

---

### ⑤ 在你自己的电脑（VS Code）—— 抄 `.env` 的值

**`.env` 不在 git 里**（`.gitignore` 排除了它，这是故意的 —— 密钥不能进仓库）。

**用 VS Code 打开 `G:\Project\my_fastapi_project\.env`，抄下这两行的值：**

- `SECRET_KEY`
- `REDIS_URL`

**（`SECRET_KEY` 可以换一串新的；**`REDIS_URL` 必须抄原样** —— 那是 Upstash 的地址。）**

---

### ⑥ 在 NAS 的 SSH 窗口 —— 建 `.env`

```bash
nano .env
```

**把下面粘进去**（`SECRET_KEY` 和 `REDIS_URL` 换成你抄的）：

```ini
APP_NAME=FastAPI Enterprise App
DEBUG=False
DATABASE_URL=sqlite+aiosqlite:///./app.db
SECRET_KEY=你抄下来的那一串
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
REDIS_URL=你抄下来的那个地址
LOG_TO_FILE=false
```

**存盘退出：`Ctrl+O` → `Enter` → `Ctrl+X`。**

**确认写进去了：**

```bash
cat .env
```

---

### ⑦ 在 NAS 的 SSH 窗口 —— 第一次构建

```bash
docker build -t myapp:0.1 .
```

**报 `permission denied` 就加 `sudo`：**

```bash
sudo docker build -t myapp:0.1 .
```

**（想以后不用 sudo：`sudo usermod -aG docker $USER`，然后重新登录 SSH。）**

---

### ⑧ 在 NAS 的 SSH 窗口 —— 第一次运行

```bash
docker run --rm -p 8000:8000 --env-file .env myapp:0.1
```

**跑起来后这个窗口会一直刷应用日志 —— 别关它，也别按 `Ctrl+C`。**

---

### ⑨ 在你自己的电脑（浏览器）

```
http://192.168.222.233:8000/health
http://192.168.222.233:8000/docs
```

- `/health` → `{"status":"ok"}`
- `/docs` → 接口文档页面

**两个都能打开，首次准备就完成了。**

## 三、让它一直在（后台常驻模式）

**上面那种前台跑法，SSH 一关就没了，NAS 重启也不会自己起来。**

**要常驻，换成这一条 —— 在 NAS 的 SSH 窗口：**

```bash
docker run -d --name myapp --restart unless-stopped -p 8000:8000 --env-file .env myapp:0.1
```

**和前台版比，多了三样、少了 `--rm`：**

| 参数 | 意思 |
| --- | --- |
| **`-d`** | **后台跑** —— SSH 关了它还在 |
| **`--name myapp`** | **给它起名字**，以后用名字指它 |
| **`--restart unless-stopped`** | **NAS 重启后自动起来** |
| **去掉 `--rm`** | **`--rm` 和 `--restart` 不能一起用**（Docker 会报冲突） |

**相关的三条命令，都在 NAS 的 SSH 窗口：**

```bash
docker logs -f myapp
```
**看日志。`-f` 是"跟着滚"。按 `Ctrl+C` 只是停止看，容器不受影响。**

```bash
docker stop myapp
```
**停掉它。**

```bash
docker rm myapp
```
**彻底删掉。** —— **注意：下次重新 `docker run --name myapp` 之前，必须先删掉旧的，否则会报名字冲突。**

## 四、常用排查命令（都在 NAS 的 SSH 窗口）

```bash
docker ps
```
**正在跑的容器。**

```bash
docker ps -a
```
**包括已经停掉的。**

```bash
docker images
```
**本地的镜像和它们的大小。**

```bash
docker logs --tail 50 myapp
```
**看最后 50 行日志。**

```bash
docker exec -it myapp sh
```
**钻进容器里看。** 进去之后是个 Linux shell，`exit` 退出。

```bash
docker history myapp:0.1
```
**看这个镜像是一层一层怎么堆出来的 —— 判断"多阶段构建到底省了什么"用这个。**

```bash
df -h
```
**NAS 磁盘还剩多少。**

## 五、兜底：NAS 上没有 git 怎么办

**先跳过「首次准备」的第四步，改用飞牛的文件管理器：**

1. 在你自己的电脑上，把项目**打包成 zip**（**先手动删掉 `.venv`、`logs`、`*.db`** —— 它们不该传上去）
2. 用飞牛的文件管理器上传 zip 到 `~`
3. 在 NAS 的 SSH 窗口里解压：

```bash
cd ~
unzip FastAPI_learning.zip
cd FastAPI_learning
```

**代价：以后每次改代码都要重新打包、重新上传。** 所以**能装 git 就装 git。**

## 六、Dockerfile 的现状（Day 15.2 之后）

**文件位置：仓库根目录的 `Dockerfile`** —— **必须是大写 `D` 开头。**

**结构记三句话：**

1. **第一个 `FROM python:3.11-slim AS builder`** —— 依赖和项目都在这里装好
2. **先 `COPY pyproject.toml uv.lock ./` 再 `RUN uv sync --no-install-project`** —— 这样**改代码不会触发重装依赖**
3. **第二个 `FROM`（最终镜像）** —— 只从 builder 搬 `/app`，构建垃圾全留在 builder 里

**现在的体积和时间（Day 15.2 实测）：**

| | 单阶段 | 多阶段 |
| --- | --- | --- |
| **镜像大小** | **314MB** | **226MB**（省 88MB） |
| **改一行代码后重建** | 重装所有依赖 | **装依赖那步显示 `CACHED`**，约 23 秒 |

**88MB 省在哪：** 55.7MB 是 uv 这个程序本身（只在 builder 里用），剩下的约 32MB 是 uv 的下载缓存和中间产物。

**⚠️ 要加一个"构建需要的新文件"时，记得在 Dockerfile 里补一行 `COPY`。**

**放在**装依赖那步之后**（和 `COPY README.md ./`、`COPY src ./src` 在一起）—— 放在前面会让改这个文件就重装依赖。**

## 七、遇到过的问题（留个记录）

| 现象 | 原因 | 怎么解决 |
| --- | --- | --- |
| `docker build` 卡在 `Sending build context` 很久 | **`.venv` 被一起打包了** | 检查 `.dockerignore` 第一行是不是 `.venv` |
| 容器日志里出现 `Installed 6 packages` | **`uv run` 默认会装 dev 依赖** | 改成多阶段构建 + 直接调 `uvicorn`（Day 15.2） |
| `permission denied` 跑 docker | 用户不在 docker 组 | 命令前加 `sudo`，或用 `usermod -aG docker` |
| 浏览器 404 | 访问的路径项目里没有 | 用 `/health` 或 `/docs` |
| **构建"成功"了，但用的是旧内容** | **文件名是小写 `dockerfile`** —— Windows 看不出来，**Linux/Docker 认的是大写 `Dockerfile`**，而 git 认得的是另一个名字 | 用 `git mv dockerfile tmp_dockerfile` + `git mv tmp_dockerfile Dockerfile` 改成大写 |
| **`failed to open file /app/README.md`** | **`uv sync` 打包项目时要读 `README.md`**（`pyproject.toml` 里写着 `readme = "README.md"`），而 Dockerfile 没 COPY 它 | Dockerfile 里加 `COPY README.md ./`，**放在装依赖之后** |
| `git status` 说 "up to date"，但其实没拉到东西 | **它比的是本地的 `origin/main` 记录** —— pull 被打断时那个记录不会更新 | 先 `git fetch origin`，再看 `git status`。**或者直接 `grep` 文件内容验证** |

**关于文件名那条，有一个值得记住的点：**

> **Docker 其实**也认小写的 `dockerfile`** —— 所以它不报错，只是构建了一个 git 从来没更新过的文件。**
>
> **不报错的错，永远比报错的错难查。**
